# CasADi-Based MPC Module Development Plan

## Summary
- Use `docs/5.2-mpc-formulation-reformulated.md` as authoritative: `theta=0` upright, `theta=pi` bottom, `V=mgl(1+cos(theta))`, and `I omega_dot = mgl sin(theta) - b omega + u`.
- Keep the current gravity sign. It already matches the 5.2 convention and current simulator behavior.
- Build the MPC module around CasADi symbolic NLP construction, not SciPy SLSQP.
- Keep implementation concentrated in `src/wsmpc/mpc/`, with only necessary config, dependency, coordinator, and visualization changes.

## Interfaces And Config
- Add `casadi>=3.6` to `pyproject.toml` and `environment.yml`.
- Add `RootConfig.mpc` with:
  - `enabled: false`
  - `split-ratios: [0.1, 0.2, 0.3]`
  - `solve-candidates-in-parallel: false`
  - `max-parallel-workers: null`
  - `horizon-steps-override: null`
  - `prediction-horizon-rule: half-natural-period`
  - `coast-mode: zero`
  - `solver: ipopt`
  - `ipopt-print-level: 0`
  - `solver-max-iterations: 100`
  - `solver-tolerance: 1.0e-6`
  - `cost` fields for `epsilon-phi`, `sigma-energy`, `q-energy`, `q-phase`, `q-local`, `q-terminal`, `rho-saturation`, `rho-delta-u`, `q-phase-diag`, and `q-local-diag`
- Keep lambda configurable through `split-ratios`; enumerate each lambda outside the NLP.
- Validate split ratios, weights, tolerances, worker counts, and matrix diagonal lengths in the Pydantic config schema.

## Implementation Changes
- Create `src/wsmpc/mpc/` with:
  - `symbolic_features.py`: CasADi expressions for energy error, phase proxy error, energy gate, local upright error, and `V_ep`.
  - `numeric_features.py`: NumPy mirror of the same feature definitions for tests, diagnostics, and visualization.
  - `casadi_dynamics.py`: CasADi continuous dynamics and RK4 discrete map matching `environment/dynamics.py`.
  - `prediction.py`: horizon calculation, split conversion, and numeric rollout of selected plans.
  - `casadi_problem.py`: builds one fixed-dimension single-shooting NLP for a given `(N_b, N_c)` with decision vector `v_0...v_{N_b-1}`, torque bounds, burst cost, zero-coast rollout cost, and terminal cost.
  - `solver.py`: wraps CasADi `nlpsol`, returns standardized candidate results, supports warm starts from zero and previous selected burst sequence.
  - `controller.py`: solves all configured split candidates, optionally in parallel CPU workers, selects the minimum successful objective, buffers burst then zero-coast actions, and falls back to configured default action on solver failure.
  - `types.py`: frozen dataclasses for split candidates, solver results, selected plans, and diagnostics.
- Add `src/wsmpc/utils/parallel.py` with an ordered process-pool map helper used only for lambda candidate solves when enabled.
- Modify `Coordinator.run_episode` minimally to accept an optional action provider. Existing default-action behavior remains the default.
- Modify CLI wiring only enough to instantiate the MPC controller when `config.mpc.enabled` is true.
- Update realtime visualization phase plotting to use `(c_phi - 1, s_phi)` from `numeric_features.py`, with target `(0, 0)`, rather than raw `(theta, omega)`.

## Test Plan
- Add CasADi-vs-NumPy parity tests for dynamics, RK4, energy error, phase proxy, energy gate, local error, and `V_ep`.
- Add convention tests confirming the current gravity sign under 5.2: small positive `theta` gives positive passive angular acceleration, and undamped unforced energy is approximately conserved over short RK4 rollout.
- Add horizon and split tests for configurable lambda arrays, `N_b >= 1`, `N_c >= 0`, and `N_b + N_c = N`.
- Add CasADi solver tests verifying finite objective, torque bounds, valid predicted trajectory shape, deterministic candidate selection, and clean fallback on solver failure.
- Add sequential-vs-parallel tests showing the same selected lambda and first action on a small deterministic candidate set.
- Update visualization tests to assert phase data is phase-proxy error, not raw theta/omega.
- Verify with `conda run -n wsmpc python -m pytest` over the new MPC tests plus `tests/test_environment.py`, `tests/test_visualization.py`, `tests/test_config_loading.py`, and `tests/test_coordinator.py`.

## Assumptions
- CasADi with IPOPT is the required first solver backend.
- The first implementation uses only torque bounds as hard NLP constraints; state limits remain diagnostic/safety checks unless later requested as path constraints.
- Learned Q critics, early wake triggers, nonzero coast inputs, CLBF constraints, and new CLI flags remain outside this implementation.
