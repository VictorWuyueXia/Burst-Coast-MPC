# Wake Sleep MPC Handoff Report

## 0. Current implementation decision

This document is the current engineering handoff for the deterministic pendulum benchmark.

The present development target is:

1. MPC only.
2. Discrete prediction map.
3. Fixed total prediction horizon.
4. Prediction horizon equal to one half of the passive natural period.
5. Burst and coast split chosen from a small finite ratio set.
6. Coast action fixed to zero.
7. No learned Q critic.
8. No early wake logic.
9. Atomic MPC module with a hot swappable cost and constraint specification file.

The current repo documents already define the larger research goal: wake sleep control, explicit burst coast structure, nonlinear pendulum benchmark, energy shaped cost, learned Q critic as a future terminal value, and early re planning as a future robustness mechanism. This handoff narrows that larger design into the first solvable implementation stage.

## 1. Continuous versus discrete prediction

Use a discrete prediction model for the MPC problem.

The continuous dynamics should still exist as the physical model, but the MPC optimizer should call a discrete update map:

```text
x_next = f_d(x, u, dt)
```

where `x` is the current state, `u` is the input, `dt` is the fixed sample time, and `f_d` is produced by RK4 integration of the continuous dynamics.

### 1.1 Why discrete prediction fits the current structure better

The controller acts at sampled simulator steps. The split ratio also becomes a number of discrete steps:

```text
N_b = max(1, round(lambda N))
N_c = N - N_b
```

Therefore, a discrete prediction model directly matches the implementation.

A discrete MPC formulation gives these practical advantages:

1. The optimizer sees a finite sequence of states and inputs.
2. The prediction horizon is exactly the number of simulator steps.
3. The burst coast split is exact at the sample level.
4. Input constraints are enforced directly at applied input samples.
5. The cost is a finite sum over prediction steps.
6. The same `f_d` can be used by simulator rollout and MPC prediction.
7. The formulation is easier to implement with SQP than continuous time collocation.
8. Single shooting is straightforward because only the burst inputs need to be decision variables.

### 1.2 What continuous prediction would provide

A continuous time optimal control formulation can be more accurate in principle. It can enforce dynamics through collocation or direct transcription over continuous intervals. It can also capture between sample constraint behavior more explicitly.

For this stage, those advantages do not justify the extra implementation cost.

Continuous prediction would require:

1. More decision variables.
2. More equality constraints.
3. A more complex transcription.
4. More complicated split handling.
5. More careful scaling.
6. More solver tuning.

### 1.3 Decision

Use continuous dynamics only to define the physical system:

```text
dot(x) = f_c(x, u)
```

Use discrete dynamics for MPC prediction and simulation:

```text
x_{i + 1} = f_d(x_i, u_i, dt)
```

The discrete map is at least as good as the continuous formulation for the current benchmark because the system is low dimensional, the time step is fixed, and the solver target is an off the shelf SQP style nonlinear program.

## 2. Model convention

Use the raw state:

```text
x = [theta, omega]^T
```

where:

1. `theta` is the pendulum angle in radians.
2. `omega` is angular velocity in radians per second.

Use this angle convention:

```text
theta = 0      downward equilibrium
theta = pi     upright target
```

Use the target state:

```text
x_star = [pi, 0]^T
```

Use continuous dynamics:

```text
dot(theta) = omega
I dot(omega) = - m g l sin(theta) - b omega + u
```

where:

1. `I` is the moment of inertia about the pivot.
2. `m` is the pendulum mass.
3. `g` is gravitational acceleration.
4. `l` is the distance from pivot to center of mass.
5. `b` is viscous damping.
6. `u` is scalar torque input.

Implementation warning:

The existing repo spec writes the gravity sign as positive in one place. With the energy convention below and target `theta = pi`, use the negative gravity sign above. Otherwise passive energy consistency will fail.

## 3. Discrete prediction map

Implement the continuous dynamics as a pure function:

```text
f_c(x, u, params)
```

Implement RK4 as:

```text
f_d(x, u, dt, params)
```

where `params` contains `I`, `m`, `g`, `l`, and `b`.

All MPC prediction must use:

```text
x_{i + 1} = f_d(x_i, u_i, dt, params)
```

Do not use an Euler integrator for the first benchmark unless it is explicitly added as a debug option.

## 4. Input limit and benchmark condition

Use scalar torque bounds:

```text
|u| <= u_max
```

The underpowered condition is:

```text
u_max < m g l
```

This makes direct static holding against gravity insufficient and forces the controller to exploit energy pumping and timing.

## 5. Natural frequency and fixed prediction horizon

Use the passive small angle natural frequency around the downward equilibrium:

```text
omega_n = sqrt(m g l / I)
```

where `omega_n` is the undamped natural angular frequency in radians per second.

The passive small angle period is:

```text
T_0 = 2 pi / omega_n
```

Use the current stage horizon:

```text
T_N = 0.5 T_0
```

Then compute the discrete horizon:

```text
N = round(T_N / dt)
```

If the pendulum is a point mass at distance `l`, then:

```text
I = m l^2
omega_n = sqrt(g / l)
T_0 = 2 pi sqrt(l / g)
```

Example with `l = 1 m`, `I = 1 kg m^2`, `m = 1 kg`, `dt = 0.02 s`:

```text
omega_n = sqrt(9.81)
omega_n = 3.13 rad/s
T_0 = 2.01 s
T_N = 1.005 s
N = 50
```

The natural period is only an initialization scale. Large amplitude pendulum motion and active torque change the realized timing. For this stage, do not optimize the total horizon. Keep `N` fixed at one half period.

## 6. Split ratio

Use a finite split ratio set:

```text
Lambda = {0.1, 0.2, 0.3}
```

For each `lambda` in `Lambda`, compute:

```text
N_b = max(1, round(lambda N))
N_c = N - N_b
```

where:

1. `N_b` is the burst horizon in steps.
2. `N_c` is the coast horizon in steps.
3. `N` is the fixed full prediction horizon.
4. `lambda` is the burst to whole horizon ratio.

Do not make `lambda` a continuous SQP decision variable. Rounding inside SQP creates nonsmooth behavior. Enumerate the three split ratios outside the solver.

## 7. Coast command for current stage

Use zero coast for the first version:

```text
u_h = 0
```

The configuration should explicitly set:

```text
coast_mode: zero
```

Do not use `hold_last` in the first version. Keep `hold_last` available as a future option:

```text
coast_mode: hold_last
u_h = v_{N_b - 1}
```

Reason:

Zero coast gives a cleaner baseline. It separates active burst authority from passive evolution. It also avoids the ambiguity that a held torque during coast may still be active control rather than genuine sleep.

## 8. Energy and phase features

The raw MPC state remains:

```text
x = [theta, omega]^T
```

Energy and phase are cost features.

Define kinetic energy:

```text
K(x) = 0.5 I omega^2
```

Define potential energy:

```text
V(x) = m g l (1 - cos(theta))
```

Define total energy:

```text
E(x) = K(x) + V(x)
```

Define upright energy:

```text
E_star = 2 m g l
```

Define normalized energy error:

```text
e_E(x) = (E(x) - E_star) / E_star
```

Choose:

```text
omega_s = sqrt(m g l / I)
```

Define phase proxy:

```text
a(theta) = sin(theta / 2)
b(omega) = omega / omega_s
r(x) = sqrt(a(theta)^2 + b(omega)^2 + eps_phi^2)
c_phi(x) = a(theta) / r(x)
s_phi(x) = b(omega) / r(x)
```

where `eps_phi > 0` is a small regularization constant.

Define phase error:

```text
e_phi(x) = [c_phi(x) - 1, s_phi(x)]^T
```

Define wrapped upright angle error:

```text
e_theta(x) = atan2(sin(theta - pi), cos(theta - pi))
```

Define local upright error:

```text
e_loc(x) = [e_theta(x), omega / omega_s]^T
```

Define energy gate:

```text
w_E(x) = exp( - e_E(x)^2 / sigma_E^2 )
```

where `sigma_E > 0` controls when phase and local stabilization become active.

## 9. Energy phase value candidate

Use this value candidate as the main state cost:

```text
V_ep(x) =
    q_E e_E(x)^2
  + q_phi w_E(x) e_phi(x)^T Q_phi e_phi(x)
  + q_loc w_E(x) e_loc(x)^T Q_loc e_loc(x)
```

where:

1. `q_E > 0` is the energy weight.
2. `q_phi >= 0` is the phase weight.
3. `q_loc >= 0` is the local upright stabilization weight.
4. `Q_phi` is a positive definite matrix.
5. `Q_loc` is a positive definite matrix.
6. `w_E(x)` is the energy gate.

Tuning order:

1. Start with energy only.
2. Add local upright stabilization.
3. Add saturation preference.
4. Add phase proxy cost.

Do not tune all terms simultaneously.

## 10. Burst, coast, and terminal costs

For burst input `u`, define normalized input:

```text
s = u / u_max
```

Use burst stage cost:

```text
ell_b(x, u, u_prev) =
    V_ep(x)
  + rho_sat (1 - (u / u_max)^2)^2
  + rho_du ((u - u_prev) / u_max)^2
```

where:

1. `rho_sat >= 0` weights near saturation preference during burst.
2. `rho_du >= 0` weights input smoothness.
3. `u_prev` is the previous applied input.

For current zero coast mode:

```text
ell_c(x) = V_ep(x)
```

Do not include a coast input penalty in the first version because:

```text
u_h = 0
```

Use terminal cost:

```text
ell_f(x_N) = q_f V_ep(x_N)
```

where `q_f > 0` is the terminal cost weight.

## 11. MPC problem for one split candidate

At decision epoch `k`, read the measured state:

```text
x_tk
```

For each `lambda` in `{0.1, 0.2, 0.3}`, solve:

```text
J_star(x_tk, lambda) =
min over v_0, ..., v_{N_b - 1}
[
    sum_{i = 0}^{N_b - 1} ell_b(x_i, v_i, v_{i - 1})
  + sum_{j = 0}^{N_c - 1} ell_c(x_{N_b + j})
  + ell_f(x_N)
]
```

Subject to:

```text
x_0 = x_tk
```

Burst dynamics:

```text
x_{i + 1} = f_d(x_i, v_i, dt, params)
for i = 0, ..., N_b - 1
```

Coast dynamics:

```text
x_{N_b + j + 1} = f_d(x_{N_b + j}, 0, dt, params)
for j = 0, ..., N_c - 1
```

Input constraints:

```text
|v_i| <= u_max
for i = 0, ..., N_b - 1
```

Optional state bounds:

```text
x_i in X
for i = 0, ..., N
```

where `X` is the allowed state set.

Select:

```text
lambda_star = argmin over lambda in Lambda of J_star(x_tk, lambda)
```

Apply only the selected plan:

```text
u_{t_k + i} = v_i_star
for i = 0, ..., N_b_star - 1
```

Then coast with zero input:

```text
u_{t_k + i} = 0
for i = N_b_star, ..., N - 1
```

Then run MPC again at the next decision epoch.

## 12. No early wake in this stage

Ignore early wake logic for the current stage.

The execution sequence is fixed:

```text
burst for N_b_star steps
coast for N_c_star steps
then re solve
```

Do not implement prediction deviation triggers, state margin triggers, or Q degradation triggers yet.

This makes the first benchmark easier to debug and makes the burst coast schedule observable without additional event logic.

## 13. SQP implementation guidance

Use single shooting first.

Decision variables:

```text
V = [v_0, v_1, ..., v_{N_b - 1}]^T
```

All states are generated by forward rollout through `f_d`.

This keeps the optimization small.

Make the problem SQP friendly:

1. Keep `N`, `N_b`, and `N_c` fixed inside each subproblem.
2. Enumerate `lambda` outside the solver.
3. Use smooth cost terms.
4. Avoid hard lower bounds such as `|u| >= eta_u u_max`.
5. Avoid absolute values in costs.
6. Avoid `round`, `if`, `min`, or `max` inside the continuous objective.
7. Normalize energy, velocity, and input.
8. Warm start each solve from the previous selected split if dimensions match.
9. If dimensions do not match, truncate or pad the previous input sequence.

Recommended solver path:

1. Use scipy SLSQP for the first prototype if speed is not critical.
2. Move to CasADi with IPOPT or SQP style methods once the formulation is stable.
3. Keep the solver interface isolated inside the MPC module.

File:

```text

```

Responsibilities:

2. Energy functions `K`, `V`, `E`.
3. Natural frequency calculation.
4. Input bound metadata.

File:

```text
dynamics/discrete_model.py
```

Responsibilities:

1. RK4 integrator.
2. Discrete map `f_d`.
3. Optional batch rollout utilities.

### 14.2 MPC module

File:

```text
mpc/split_ratio_mpc.py
```

Responsibilities:

1. Read `N`, `Lambda`, and `coast_mode`.
2. For each split ratio, compute `N_b` and `N_c`.
3. Build the single shooting objective.
4. Call solver.
5. Compare candidate split costs.
6. Return selected split and burst input sequence.

The MPC module should not hard code the pendulum cost. It should depend on a hot swappable specification object.

### 14.3 Solver interface

File:

```text

```

```text

    objective_value
    decision_variables
    solve_time
    message
```

### 14.4 Prediction rollout module

File:

```text

```

Responsibilities:

1. Roll out burst dynamics.
2. Roll out zero coast dynamics.
3. Return full predicted state and input sequence.
4. Compute per step cost terms for logging.

## 15. Hot swappable cost and constraint specification

Implement a separate specification file for cost and constraints.

File:

```text
specs/energy_phase_pendulum.py
```

This file defines the cost and constraints used by MPC.

Required interface:

```text
class CostConstraintSpec:
    def features(self, x, params):
        ...

    def value_candidate(self, x, params):
        ...

    def burst_stage_cost(self, x, u, u_prev, params):
        ...

    def coast_stage_cost(self, x, params):
        ...

    def terminal_cost(self, x, params):
        ...

    def input_constraints(self, u, params):
        ...

    def state_constraints(self, x, params):
        ...
```

The MPC module calls only this interface. Therefore, a future cost and constraint design can be swapped in without rewriting the optimizer.

Examples of future spec files:

```text
specs/quadratic_local_pendulum.py
specs/energy_only_pendulum.py
specs/clbf_pendulum.py
specs/spacecraft_rendezvous.py
```

Do not place solver logic inside the spec file. The spec file only defines mathematical functions.

## 16. Configuration file

Use a YAML config for the first stage.

Recommended config:

```text
model:
  m: 1.0
  l: 1.0
  I: 1.0
  g: 9.81
  b: 0.05
  u_max_ratio: 0.7

time:
  dt: 0.02
  horizon_rule: half_natural_period

mpc:
  prediction_model: discrete_rk4
  shooting: single
  split_ratios: [0.1, 0.2, 0.3]
  coast_mode: zero
  solver: slsqp

cost:
  sigma_E: 0.5
  eps_phi: 1.0e-6
  q_E: 1.0
  q_phi: 0.0
  q_loc: 0.0
  q_f: 5.0
  rho_sat: 0.0
  rho_du: 1.0e-3

  epsilon_theta: 0.10
  epsilon_omega: 0.20
  hold_steps: 50
```

Compute:

```text
u_max = u_max_ratio * m * g * l
```

Do not set `u_max` independently unless a config override is explicitly provided.

## 17. Execution loop

At each decision epoch:

1. Read current state `x_tk`.
2. Compute natural frequency and fixed horizon `N` from config.
3. For each split ratio in `{0.1, 0.2, 0.3}`:
   1. Compute `N_b` and `N_c`.
   2. Solve the burst input sequence with SQP.
   3. Roll out zero coast.
   4. Compute full horizon cost.
4. Select the split with minimum objective.
5. Apply burst input sequence.
6. Apply zero coast for the remaining steps.
7. Log trajectory, split ratio, solver status, energy, and costs.
8. Repeat at the next planned decision epoch.

No early wake trigger is used in this stage.

## 18. Tests required before tuning

### 18.1 Energy consistency

With:

```text
u = 0
b = 0
```

energy should remain nearly constant over short simulation.

Expected:

```text
max |E(t) - E(0)| < tolerance
```

If this fails, check the gravity sign and RK4 implementation.

### 18.2 Discrete model shape

For input state shape `(2,)`, `f_d` should return shape `(2,)`.

### 18.3 Natural period horizon

Given model parameters and `dt`, verify:

```text
N = round(0.5 * (2 pi / omega_n) / dt)
```

### 18.4 Split ratio dimensions

For every split ratio:

```text
N_b >= 1
N_c >= 0
N_b + N_c = N
```

### 18.5 Zero coast rollout

After the burst segment, all predicted coast inputs should equal zero.

### 18.6 Cost near target

At:

```text
theta = pi
omega = 0
```

`V_ep` should be near zero.

### 18.7 Input bounds

All optimized burst inputs must satisfy:

```text
|v_i| <= u_max
```

Log these for every episode:

2. Final state.
3. Time step.
4. Full state trajectory.
5. Full input trajectory.

## 20. Deferred features

Do not implement these in the first version:

1. Learned Q critic.
2. Learned value function.
3. Hold last coast mode.
4. Early wake trigger.
5. Piece wise linear model.
6. Model mismatch.
7. Process noise.
8. CLBF constraints.
9. Multi node architecture.
10. Parallel MPC solve.
11. Spacecraft benchmark.

## 21. Future extension path

After the deterministic zero coast split ratio MPC works:

1. Enable `hold_last` as an alternative coast mode.
2. Add early wake trigger.
3. Add learned terminal Q value.
4. Replace explicit terminal cost with Q terminal score.
5. Add CLBF constraints based on `V_ep`.
6. Add noise and model mismatch.
7. Add spacecraft style burst coast benchmark.

The terminal score should already be isolated as an interchangeable component:

```text
terminal_score = terminal_cost_spec.evaluate(...)
```

Current stage:

```text
terminal_score = q_f V_ep(x_N)
```

Future learned Q stage:

```text
terminal_score = alpha_Q Q_theta(x_{N_b}, u_h, N_c)
```

This interface prevents the future learning module from forcing a rewrite of the MPC solver.
