# Neural Network Design for Burst-Coast MPC

## Design Purpose

The neural network is a strategic cost critic for the burst-coast MPC wrapper. It does not learn pendulum dynamics, does not output torque, and does not replace the MPC optimizer. MPC remains the inner torque planner; the learned layer only scores the normalized burst-horizon action

$$
a_k=
\begin{bmatrix}
\bar B_k\\
\bar H_k
\end{bmatrix}
\in \mathcal A .
$$

At each replanning epoch, the policy evaluates the discrete action grid and selects the lowest predicted closed-loop cost:

$$
a_k^\star=\arg\min_{a\in\mathcal A}\hat Q(s_k,a).
$$

There is no separate actor network. The actor is the deterministic $\arg\min$ over the two-dimensional action matrix. During training, exploration samples from the same matrix with a cost-softmax distribution.

## Replanning-Level Formulation

The RL time index $k$ is a replanning index, not a simulator step. One RL transition corresponds to executing one burst-coast MPC plan from the observation at the start of the segment to the next replanning observation.

The action is realized as integer MPC dimensions:

$$
H_k=\max(1,\operatorname{round}(\bar H_k H_{\max})),
$$

$$
B_k=\max(1,\operatorname{round}(0.5\bar B_k H_k)),
$$

$$
C_k=H_k-B_k.
$$

Here $H_{\max}$ is the natural-period prediction horizon, $B_k$ is the active burst length, and $C_k$ is the passive coast length. The action grid remains normalized in $(\bar B,\bar H)$, while the MPC receives the realized integer dimensions.

The current Monte Carlo artifact contract stores the replanning state as

$$
s_k=
\begin{bmatrix}
\sin\theta_k\\
\cos\theta_k\\
\omega_k
\end{bmatrix}.
$$

For NN input, use the derived feature vector

$$
z_k=
\begin{bmatrix}
\sin\theta_k\\
\cos\theta_k\\
\omega_k/\omega_{\mathrm{ref}}\\
e_E(x_k)
\end{bmatrix},
$$

where

$$
e_E(x_k)=\frac{E(x_k)-E^\star}{E^\star}.
$$

This keeps the logged data contract compact while exposing the phase, angular speed, and energy condition that govern swing-up timing.

## Training Target

The critic approximates the expected closed-loop return from the current replanning state and selected burst-horizon action:

$$
\hat Q(s_k,a_k)\approx \mathbb E[G_k\mid s_k,a_k].
$$

The Monte Carlo dataset provides the sampled return:

$$
G_k=c_k+\gamma G_{k+1},
$$

with the immediate replanning cost

$$
c_k=
w_t\Delta t_k
+
w_u\sum_{j\in k}\left(\frac{u_j}{u_{\max}}\right)^2
+
w_c\frac{t_{\mathrm{solve},k}}{T_s}
+
P_{\mathrm{fail}}\mathbf 1_{\mathrm{terminal\ fail}}.
$$

The current `rl_steps.csv` rows already contain the required state, action, realized dimensions, solve time, immediate cost, return cost, terminal flag, and executed torque sequence. The first offline trainer should fit directly to `return-cost`.

## Structured Residual Critic

Use a physics-residual cost critic:

$$
\hat Q(s_k,a_k)=Q_{\mathrm{phys}}(s_k,a_k)+R_\psi(z_k,a_k).
$$

The explicit term captures cost trends that are known before the candidate is executed:

$$
Q_{\mathrm{phys}}(s_k,a_k)
=
\lambda_t T(B_k,H_k)
+
\lambda_c \hat t_{\mathrm{solve}}(B_k,H_k)
+
\lambda_u \hat U(B_k,H_k).
$$

Use

$$
T(B_k,H_k)=H_kT_s
$$

for physical duration. Fit the computation model from logged solve times with the smallest adequate nonnegative model:

$$
\hat t_{\mathrm{solve}}(B,H)
=
\alpha_0+\alpha_HH+\alpha_BB+\alpha_{HB}HB.
$$

Use a deployment-available effort proxy:

$$
\hat U(B_k,H_k)=B_k
$$

This proxy must not depend on solving every MPC candidate, because deployment scores the grid before calling MPC once.

The residual network learns the hard part: phase-energy timing, terminal risk, and future value beyond the local candidate cost. It should stay small:

$$
[z_k,\bar B_k,\bar H_k]
\rightarrow
\mathrm{Linear}(6,32)
\rightarrow
\mathrm{ReLU}
\rightarrow
\mathrm{Linear}(32,16)
\rightarrow
\mathrm{ReLU}
\rightarrow
\mathrm{Linear}(16,1)
\rightarrow
R_\psi.
$$

ReLU is preferred because the resulting affine-ReLU-affine mapping remains piecewise affine and is easier to inspect later than a saturated activation model.

The trainable structured weights are constrained nonnegative:

$$
\lambda_i=\operatorname{softplus}(\eta_i),
\qquad
\alpha_i=\operatorname{softplus}(\beta_i).
$$

Initialize $\lambda_t$, $\lambda_u$, $\lambda_c$ from the data-generation cost weights. The optimizer may rescale them because $Q_{\mathrm{phys}}$ is a local candidate-level estimate while $G_k$ is an accumulated closed-loop return.

Train the critic with the end-to-end regression loss:

$$
\mathcal L(\psi,\eta)
=
\left(
Q_{\mathrm{phys}}(s_k,a_k)
+
R_\psi(z_k,a_k)
-
G_k
\right)^2.
$$

The residual-only target

$$
G_k-Q_{\mathrm{phys}}(s_k,a_k)
$$

is useful for diagnostics, but the deployed model should be trained and evaluated as the full structured critic.

## Deployment Logic

At a replanning observation:

1. Build the normalized action grid $\mathcal A=\{(\bar B_i,\bar H_j)\}$.
2. Map every candidate to integer $(B_{ij},H_{ij})$.
3. Broadcast the current feature vector $z_k$ across the grid.
4. Evaluate $\hat Q(s_k,a_{ij})$ for every candidate.
5. Select the minimum-cost action.
6. Call the existing MPC controller once with the selected dimensions.

The deployed controller remains:

$$
s_k
\rightarrow
\hat Q(s_k,\mathcal A)
\rightarrow
(\bar B_k^\star,\bar H_k^\star)
\rightarrow
\mathrm{MPC}(B_k,H_k)
\rightarrow
u.
$$

The normal MPC controller must remain independently runnable without the NN.

## Training And Evaluation Action Plan

### Step 1 - Freeze the dataset contract

Use `rl_steps.csv` as the offline critic dataset. Required columns are:

- `s-sin-theta`, `s-cos-theta`, `s-omega-rad-s`
- `bbar`, `hbar`, `burst-steps`, `horizon-steps`
- `step-cost`, `return-cost`, `solve-time-s`
- `done`, `u-nm-json`, `plan-id`

Compute $e_E$, $\omega_{\mathrm{ref}}$, $B/H$, and other derived model features in the training dataset loader, not in the Monte Carlo generator.

### Step 2 - Build the training dataset

Load all selected Monte Carlo artifact folders, concatenate their `rl_steps.csv` files, and split by episode or run directory. Fit normalization statistics on the training split only, then apply the same statistics to validation and deployment.

The supervised tuple is

$$
(z_k,\bar B_k,\bar H_k,B_k,H_k,G_k).
$$

The first target is the logged Monte Carlo `return-cost`; no bootstrapping is needed for the offline pretraining pass.

### Step 3 - Fit the structured cost components

Fit $\hat t_{\mathrm{solve}}(B,H)$ from `solve-time-s`. Keep the model nonnegative and monotone in the practical action domain. Initialize the physical weights from the data-generation weights:

$$
\lambda_t\leftarrow w_t,\qquad
\lambda_u\leftarrow w_u,\qquad
\lambda_c\leftarrow w_c.
$$

Train the lambdas jointly with the residual critic.

### Step 4 - Train the residual Q critic

Train the small residual MLP on the full critic loss. Report:

- training and validation mean squared error on `return-cost`
- error by action-region in $(\bar B,\bar H)$
- error by state-region in phase-energy space
- learned $\lambda$ values and solve-time fit quality

The main diagnostic is whether the residual critic improves validation error over $Q_{\mathrm{phys}}$ alone while preserving interpretable monotone cost trends.

### Step 5 - Validate the induced grid policy offline

For held-out rows, compare the logged sampled action with the critic-minimizing action. This is not an optimality proof, because the dataset contains Monte Carlo samples rather than exhaustive labels. It is a policy sanity check: selected actions should avoid obviously high time, high compute, and high failure-risk regions.

Also plot $\hat Q(s,\bar B,\bar H)$ surfaces for representative states near downward, high-energy swing, near-upright, and failed-terminal neighborhoods.

### Step 6 - Integrate inference around the existing MPC controller

Add a narrow RL action provider that accepts the current observation, evaluates the action grid, returns the selected normalized action, and lets the existing MPC path solve the selected burst-coast plan. Do not merge training logic into `Coordinator.run_episode()`.

The normal run path should have only one new decision boundary:

$$
\text{observation}
\rightarrow
\text{RL grid scorer}
\rightarrow
\text{selected Monte Carlo action}
\rightarrow
\text{existing MPC plan execution}.
$$

### Step 7 - Run simulated online refinement

After offline validation, use the NN-selected policy in simulation with cost-softmax exploration:

$$
p(a\mid s)
=
(1-\epsilon)
\frac{\exp(-\hat Q(s,a)/\tau)}
{\sum_{a'\in\mathcal A}\exp(-\hat Q(s,a')/\tau)}
+
\epsilon\frac{1}{|\mathcal A|}.
$$

Log the same replanning-level fields as Monte Carlo data generation. Continue fitting with Monte Carlo returns first; introduce TD targets only after the supervised offline pipeline is stable.

## Final Design Decisions

The project should implement one small structured Q-cost critic:

$$
\boxed{
\hat Q(s,a)=Q_{\mathrm{phys}}(s,a)+R_\psi(z,a).
}
$$

The NN learns residual strategic value over the burst-horizon grid. MPC continues to solve torque. Deployment selects one grid action by $\arg\min\hat Q$ and calls MPC once. The first training pass is offline supervised regression from Monte Carlo `return-cost`, using the current `rl_steps.csv` artifact contract.
