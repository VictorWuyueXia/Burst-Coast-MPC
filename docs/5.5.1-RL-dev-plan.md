# Step 1 Plan: Monte Carlo Data Generation for Offline RL

## Summary

Add a narrow data-generation path that runs the existing natural-period MPC simulation under one sampled `(Bbar, Hbar)` action per replanning epoch. Keep normal `run-episode`, `Coordinator.run_episode`, MPC objective logic, and `steps.csv` behavior intact. The new path writes an RL-focused `rl_steps.csv` beside the existing dense `steps.csv`, then computes Monte Carlo returns backward at episode end.

Style rule for implementation: compact streamline-of-logic files, no stage/dev-version comments, no fallback behavior, no unnecessary CLI/config breadth, no parallel compute, and concise professional comments only for key code blocks.

## Interfaces And Structure Budget

Planned structure budget, not to exceed:

- New config file: `configs/data-generation/config.yaml`
- New workflow file: `src/wsmpc/data_generation.py`
- New utility file: `src/wsmpc/utils/monte_carlo.py`
- New config models: `DataGenerationConfig`, `DataGenerationRootConfig`
- New data objects: `MonteCarloAction`, `RLStepRecord`
- New controller methods: `start_monte_carlo_plan(...)` on `CasadiMPCController` and `NaturalPeriodMPCController`
- New CLI command: `wsmpc generate-mc-data`
- New artifact method: `ArtifactWriter.write_rl_steps(...)`

Config parameters in `data-generation`:

- `episodes`
- `seed`
- `gamma`
- `bbar-min`=0, `bbar-max`
- `hbar-min`=1, `hbar-max`=0.5*`bbar-max`
- `time-weight`
- `action-weight`
- `compute-weight`
- `fail-penalty`

Default action semantics:

- Sample per replan, not per episode.
- `H_steps = round(Hbar * Hmax_steps)`, where `Hmax_steps` is the current natural-period horizon.
- `B_steps = round(Bbar * Bmax_steps)`.
- Invalid actions raise immediately rather than being clamped.
- `runtime.max-worker-threads: 1`; the data path solves exactly one candidate directly, without `ordered_process_map`.
- There should be no event trigger logic activated for the data generation run.

## Implementation Changes

- Add `load_data_generation_config()` to validate only `configs/data-generation/config.yaml` as a full runtime config plus required `data-generation`; do not make existing `standard` or `default` configs carry optional RL fields.
- Add `sample_uniform_monte_carlo_action(rng, config, environment)` in `utils/monte_carlo.py`.
- Add `start_monte_carlo_plan(observation, action)` to the natural-period controller; it builds one `SplitCandidate`, calls `solve_candidate(...)` directly, stores the active plan, and logs `Bbar`, `Hbar`, `burst_steps`, `horizon_steps`, and solve time.
- Add `MonteCarloDataGenerator.run()` to execute episodes at replanning granularity:
  - observe `s_k = [sin(theta), cos(theta), omega]`;
  - sample one action;
  - solve one MPC plan;
  - execute the plan through the existing `Environment.step(...)`;
  - collect dense `StepRecord`s into `steps.csv`;
  - collect one `RLStepRecord` per replan into memory;
  - compute `G_k = c_k + gamma * G_{k+1}` backward after the episode;
  - write `rl_steps.csv`.
- Define `c_k` as the selected plan-cost signal:
  `time_weight * physical_duration + action_weight * sum((u_applied/u_max)^2) + compute_weight * solve_time_s/Ts + terminal_fail_penalty`.
- Mark `done` only when the transition ends the episode by goal, max steps, or interruption. Apply `fail-penalty` only for terminal non-goal endings.

`rl_steps.csv` columns:

- `run-id`, `episode-id`, `replan-index`
- `start-t-index`, `start-t-sec`, `end-t-index`, `end-t-sec`
- `s-sin-theta`, `s-cos-theta`, `s-omega-rad-s`, `s-action-sum`
- `bbar`, `hbar`, `burst-steps`, `horizon-steps`
- `next-s-sin-theta`, `next-s-cos-theta`, `next-s-omega-rad-s`, `next-s-action-sum`
- `done`, `step-cost`, `return-cost`
- `u-nm-json`, `solve-time-s`, `plan-id`

## Test Plan

- Config test: `load_data_generation_config()` loads `configs/data-generation/config.yaml`; missing or invalid generation fields fail schema validation.
- Utility test: sampled `(Bbar, Hbar)` stays inside configured uniform ranges and maps to valid positive `H_steps` and `B_steps`.
- Controller test: `start_monte_carlo_plan(...)` solves one forced candidate and does not enumerate configured split ratios.
- Artifact test: `write_rl_steps(...)` creates `rl_steps.csv`, manifest includes it, and row counts match generated RL records.
- CLI smoke test: `wsmpc generate-mc-data` with a small monkeypatched config writes both `steps.csv` and `rl_steps.csv`.
- Verification command: `conda run -n wsmpc python -m pytest`.

## Assumptions

- The first dataset uses per-replan uniform action sampling and the plan-cost return signal.
- Existing `steps.csv` remains the dense simulator-step artifact; `rl_steps.csv` is the RL transition artifact.
- Existing `Coordinator.run_episode` stays unchanged for normal MPC runs.
- The active controller remains `IP-dynamics-naturalPeriod`; archived MPC code is out of scope.
