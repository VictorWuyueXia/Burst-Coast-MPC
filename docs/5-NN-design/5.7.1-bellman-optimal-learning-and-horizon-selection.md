# 5.7.1 Bellman-Optimal Learning and Horizon Selection

## Recommendation

The simplest defensible direction is:

1. Treat one fully executed burst-coast plan as one decision transition.
2. Build a finite transition graph with the known simulator and current MPC.
3. Solve its cost-to-go by reverse graph search or tabular dynamic programming.
4. Use the solved table directly first; train a neural action-value model only as supervised distillation.
5. If the table becomes too large, replace it with synchronous model-based fitted Q iteration.

This is simpler and more reliable than actor-critic for the present finite timing-action grid. It also corrects the Monte Carlo mismatch: random trajectories remain useful sources of states and transitions, but their random-continuation returns are not optimal-value labels.

For horizon optimization, do not make a monotone-binary nonlinear program the main direction. First parallelize fixed $(B,H)$ continuous solves. If that is still too slow, a small set of GPU-batched model predictive path integral (MPPI) horizon anchors is more feasible than a nonconvex mixed-integer nonlinear program. Use the learned Bellman value as MPPI's terminal cost and validate the best few samples with the exact model.

## 1. Define the Bellman problem at the correct decision level

Use the replanning event, rather than one physics step, as the decision index. A minimal Markov state for the current implementation is

$$
s=(\theta,\omega,u_-,r,g_h).
$$

Here $\theta$ is the unwrapped pendulum angle, $\omega$ is angular velocity, $u_-$ is the previously applied signed torque, $r$ is the number of simulation steps remaining before the episode limit, and $g_h$ is the current consecutive-goal hold count. The previous torque is required because the MPC objective contains a torque-change term. The remaining budget and hold count are required because failure and successful termination depend on them. Sine, cosine, energy error, and constraint margin are derived network features, not additional physical states. The current angle and speed limits are diagnostic; they must be added to the transition feasibility test before they can support a hard-constraint claim.

The timing action is

$$
a=(B,H)\in\mathcal A(s).
$$

Here $B$ is the number of actuated burst steps, $H$ is the total number of steps before the next planned replan, and $\mathcal A(s)$ is the set of feasible distinct integer timing pairs at state $s$. The coast contains $H-B$ exact zero-torque steps.

Let the deterministic event simulator return

$$
\mathcal T(s,a)=(s^+,c,d,\delta).
$$

Here $s^+$ is the next decision or terminal state after fully executing the selected plan, $c$ is its immediate project cost, $d$ is the number of physics steps actually executed, and $\delta$ is one when the event terminates the episode and zero otherwise. Terminal or maximum-step termination may make $d<H$.

The Bellman-optimal scheduler satisfies

$$
Q^*(s,a)=c(s,a)+\bigl(1-\delta(s,a)\bigr)
\min_{a'\in\mathcal A(s^+)}Q^*(s^+,a').
$$

Here $Q^*(s,a)$ is the minimum total remaining cost after choosing $a$ now and acting optimally later, while $a'$ is a candidate timing action at the successor state. Lower cost is better. No discount is needed: the task has a finite step budget, explicit duration cost, and an absorbing terminal condition.

This equation gives the optimal timing scheduler around the fixed low-level MPC. It is not automatically the globally optimal joint torque-and-timing controller. That stronger target would require

$$
Q^*(s,B,H)=\min_{\mathbf u}
\left[c(s,B,H,\mathbf u)+V^*\!\left(F(s,B,H,\mathbf u)\right)\right].
$$

Here $\mathbf u$ is the complete continuous burst-torque sequence, $F$ is the known full-event transition under that sequence, and $V^*$ is optimal cost remaining at the event endpoint. The current inner MPC minimizes a local horizon objective without this downstream $V^*$ term, and IPOPT may return a local solution. Dynamic programming outside that MPC can optimize horizon choices for the resulting controller, but it cannot repair a locally suboptimal torque edge.

For a clean training contract, fully execute every selected torque sequence before replanning. Only terminal success or the fixed maximum-step boundary should end it early. If online event triggering remains enabled and truncates actions, it must either be included in $\mathcal T$ everywhere or disabled for both training and deployment.

## 2. Why the Monte Carlo target is different

The existing random-rollout return estimates

$$
Q^\mu(s,a)=\mathbb E_\mu
\left[\sum_{j=k}^{T}c_j\;\middle|\;s_k=s,\ a_k=a\right].
$$

Here $\mu$ is the random future timing policy, $k$ is the current replanning event, $T$ is the terminal event, and $c_j$ is the cost of event $j$. This is the expected cost after taking $a$ once and then following $\mu$. It is a valid value for the random behavior policy, but it is not $Q^*$.

Keep the Monte Carlo states and one-event transitions. Stop using their stored return-cost values as final optimality labels. Bellman labels must compare counterfactual actions from the same state and minimize over future actions.

## 3. Simplest exact reference: forward edges, then reverse graph search

The set of all continuous predecessor states is uncountable, so an exact exhaustive backtrace is unavailable without a finite abstraction. There is also no need to solve inverse dynamics. Construct all discretized edges forward once:

1. Discretize the bounded Markov state into nodes $s_i$.
2. Deduplicate normalized timing coordinates that map to the same integer $(B,H)$.
3. From every node $s_i$, solve and fully execute every retained timing action $a$.
4. Store cost, successor, feasibility, executed duration, and terminal status; represent goal and deadline failure as absorbing terminal nodes.
5. Map each nonterminal successor to a node and add the directed edge

$$
s_i
\xrightarrow[\text{cost }c_{i,a}]{a}
s'_{i,a}.
$$

Here $c_{i,a}$ is the nonnegative event cost and $s'_{i,a}$ is the quantized successor produced by action $a$ from node $s_i$.

Reverse these stored edges. If every event has unit primary cost and failure is forbidden, multi-source breadth-first search from all goal nodes gives the minimum remaining event count. For the weighted nonnegative project cost, seed goal terminals with zero and failure terminals with the configured failure penalty, then run multi-source Dijkstra. Equivalently, put the failure penalty on each incoming failure edge and seed its terminal with zero. This is exactly the user's goal, minus-one-event, minus-two-event construction, but graph search propagates all layers without neural training between them.

If off-grid successors must be interpolated instead of assigned to one node, use synchronous value iteration:

$$
V_0(s_i)
=
\begin{cases}
0, & s_i\in\mathcal X_f,\\
P_{\mathrm{fail}}, & s_i\in\mathcal X_{\mathrm{fail}},\\
+\infty, & \text{otherwise},
\end{cases}
$$

$$
V_{m+1}(s_i)=
\min\left\{V_m(s_i),\min_{a\in\mathcal A(s_i)}
\left[c_{i,a}+\mathcal I[V_m](s'_{i,a})\right]\right\}.
$$

Here $\mathcal X_f$ is the terminal goal set, $\mathcal X_{\mathrm{fail}}$ is the deadline-failure set, $P_{\mathrm{fail}}$ is its terminal penalty, $V_m$ is the best known cost using at most $m$ future events, and $\mathcal I[V_m]$ interpolates the previous table at an off-grid successor. One synchronous sweep propagates terminal information one event farther. Use $+\infty$ instead of $P_{\mathrm{fail}}$ when successful completion is a hard requirement.

For the pendulum, use a coarse table as the reference and treat $r$ and $g_h$ as discrete DP layers. If the previous-torque axis makes the table too large, either require every action to finish with at least one zero-torque coast step so $u_-=0$ at every decision, or move to fitted Q iteration. Do not silently omit a variable on which the transition, cost, or termination depends.

After the table is solved, distill each cached edge with the fixed label

$$
y_{i,a}=c_{i,a}+(1-\delta_{i,a})V_{\mathrm{DP}}(s'_{i,a}).
$$

Here $V_{\mathrm{DP}}$ is the solved table and $\delta_{i,a}$ is the terminal flag for that edge. Fit all labels once as ordinary supervised data and validate that the network preserves the table's action ranking.

## 4. Do not use a one-sided neural update

Do not update the network only when its predicted cost is greater than the DP minimum. If the correct target is $10$ and the network predicts $5$, that rule makes no correction; the policy can then select the falsely cheap action.

Fit every target in both directions:

$$
\mathcal L(\phi)=\frac{1}{N}\sum_{i=1}^{N}
\left(Q_\phi(s_i,a_i)-y_i\right)^2.
$$

Here $\phi$ is the network parameter vector, $N$ is the number of supervised state-action rows, $Q_\phi$ is the predicted cost, and $y_i$ is the frozen DP or Bellman target. For cost minimization, underestimation is more dangerous than overestimation because the policy deliberately chooses the smallest prediction.

Monotone downward updates are meaningful for an exact table initialized with certified upper bounds. They are not safe for a shared neural network: one gradient update changes many unobserved states. The simplest reliable sequence is therefore “solve table, then distill,” not “change the table and network together.”

## 5. If the table is too large: model-based fitted Q iteration

Fitted Q iteration is the simplest neural Bellman method that matches the current deployment, because the deployed policy already chooses an explicit minimum over a finite timing grid. Use this procedure:

1. Freeze the plant, cost, terminal definition, timing lattice, inner controller, event boundary, and calibrated computation-cost model.
2. Build a state bank from the existing Monte Carlo states, low-discrepancy samples over the admissible domain, greedy-policy states, and dense samples near the goal and constraint boundaries.
3. Reset the complete simulator state and branch every affordable distinct $(B,H)$ action from each state. These same-state counterfactual branches are more useful than unrelated random episodes.
4. Fully execute each branch and cache

$$
\mathcal D=\left\{(s_i,a_i,c_i,s_i',\delta_i)\right\}_{i=1}^{N}.
$$

Here $\mathcal D$ is the transition dataset, $c_i$ is immediate event cost, $s_i'$ is the successor, and $\delta_i$ marks termination.

5. Freeze a target critic $Q_{\bar\phi}$ and calculate

$$
y_i=c_i+(1-\delta_i)
\min_{a'\in\mathcal A(s_i')}Q_{\bar\phi}(s_i',a').
$$

Here $\bar\phi$ denotes parameters held fixed for the entire Bellman sweep. The minimization is a batched reduction over all unique successor actions.

6. Train $Q_\phi$ on every frozen $y_i$ until the supervised validation error stops improving.
7. Copy $\phi$ to $\bar\phi$ only after the sweep, then recompute every target.
8. Add successors, uncertainty states, and states visited by the new greedy policy; never replace replay with only the latest episode.
9. Stop when held-out Bellman residual, same-state action regret, greedy action choice, and deterministic closed-loop cost all stop improving.

The repository already contains the one-step target formula in StructuredCriticPolicy.fitted_q_targets. Its present limitations are data coverage, an incomplete Markov input, and online replay rebuilt from only the latest episode—not the Bellman equation itself. The offline Monte Carlo return regression should remain only as a behavior-policy reference.

This method is approximate dynamic programming, not actor-critic. An actor-critic method has a learned actor $\pi_\psi(a\mid s)$ with parameters $\psi$ and a learned critic that evaluates that actor. Here the actor is unnecessary: the policy is the exact finite-grid operation

$$
\pi_\phi(s)=\arg\min_{a\in\mathcal A(s)}Q_\phi(s,a).
$$

Actor-critic becomes useful only if timing actions become continuous or too numerous to enumerate. Until then it adds another approximation and another training loop.

In conventional model-free RL, the simplest equivalents are tabular Q-learning for a finite state table and a deep Q-network (DQN) when a neural approximator is required. They apply the same one-step Bellman target to experienced transitions. The known resettable simulator makes batch fitted Q iteration simpler here because it can generate deliberate same-state counterfactual actions instead of waiting for exploration to encounter them.

## 6. Parallelize transition generation, not neural updates

The simplest parallel architecture is synchronous:

1. Form the Cartesian workload of state nodes and distinct timing actions.
2. Shard those independent state-action jobs across CPU processes.
3. Give each worker its own CasADi/IPOPT solver objects and limit nested BLAS threads.
4. Return deterministic full-event costs and successors to one transition store.
5. Cache transitions, because later Bellman sweeps reuse them.
6. Batch all successor-action network evaluations on one GPU and reduce with a minimum.
7. Train one central network, then publish one frozen target only between sweeps.

This follows the same high-level “many actors, one learner” pattern used in distributed RL, without asynchronous stale policies or importance corrections. Asynchronous Advantage Actor-Critic (A3C) and Importance-Weighted Actor-Learner Architecture (IMPALA) are useful precedents for parallel experience generation, but their actor-critic machinery is unnecessary here.

Use a frozen calibrated solve-time model inside DP labels. Parallel wall time contains worker contention and is not an intrinsic action cost. Report actual online latency separately.

## 7. Why the monotone-binary formulation is not the main answer

For a fixed total horizon, the correct prefix formulation is

$$
z_i\in\{0,1\},\qquad z_{i+1}\le z_i,\qquad
-u_{\max}z_i\le u_i\le u_{\max}z_i,\qquad
B=\sum_{i=0}^{H-1}z_i.
$$

Here $z_i$ enables torque at step $i$, $u_i$ is the continuous torque, and $u_{\max}$ is its magnitude bound. The non-strict inequality permits a prefix of ones followed by zeros. A strict inequality is wrong: after the first forced transition to zero, the next binary pair cannot satisfy another strict decrease.

This does not eliminate the burst decision. It replaces one switching index with $H$ binary variables and normally $H$ torque slots. With $z_0=1$, there are only $H$ feasible prefix lengths; allowing $B=0$ gives $H+1$. Direct enumeration is therefore the specialized exact combinatorial solver.

There is also a structural degeneracy when the objective depends only on the state and applied-torque trajectory, not on the enable mask itself. Let $\mathcal U_B$ be the feasible control set with burst length $B$. If $B_1<B_2$, then

$$
\mathcal U_{B_1}\subseteq\mathcal U_{B_2}
\quad\Longrightarrow\quad
J^*(B_2)\le J^*(B_1).
$$

Here $J^*(B)$ is the minimum objective for a fixed burst length. The implication holds because the longer burst can set its extra permitted torques to zero and reproduce every shorter-burst solution. A cost that explicitly depends on $\sum_i z_i$, predicted computation, or different burst/coast stage accounting can break this degeneracy, but then the burst decision has entered the objective rather than disappeared.

The current five-natural-period horizon is about $1004$ physics steps. The existing solver optimizes only the burst torque variables for one fixed candidate and uses IPOPT, a continuous local nonlinear-programming solver. The binary version would require a new mixed-integer solver for a long nonconvex mixed-integer nonlinear program (MINLP). It should be kept as a coarse linearized mixed-integer quadratic program (MIQP) benchmark or a formulation reference, not the primary online controller.

## 8. More feasible alternative: fixed-anchor batched MPPI

Let $a=1,\ldots,A$ index a small, deduplicated set of anchor pairs $(B_a,H_a)$, and let $k=1,\ldots,K$ index sampled torque sequences for each anchor. Define the exact burst mask and sampled control by

$$
m_{a,t}=\mathbf 1_{\{t<B_a\}},
$$

$$
u_{a,k,t}=m_{a,t}\operatorname{clip}
\left(\bar u_{a,t}+\epsilon_{a,k,t},-u_{\max},u_{\max}\right).
$$

Here $t$ is the rollout step, $m_{a,t}$ is one during the burst and zero during coast, $\bar u_{a,t}$ is the nominal sequence, and $\epsilon_{a,k,t}$ is sampled exploration noise. Clipping enforces the torque bound and the mask enforces exact zero coast.

Roll out the known RK4 dynamics in parallel and score

$$
S_{a,k}=\sum_{t=0}^{H_a-1}\ell(x_{a,k,t},u_{a,k,t})
+\widehat V(x_{a,k,H_a}).
$$

Here $x_{a,k,t}$ is the state of rollout $k$ for anchor $a$, $\ell$ is the Bellman-consistent stage cost, and $\widehat V$ is the frozen DP-distilled terminal cost. The network supplies far-horizon value; it should not replace the known dynamics.

Within each anchor, use exponential weights

$$
w_{a,k}=
\frac{\exp\!\left(-(S_{a,k}-S_{a,\min})/\lambda\right)}
{\sum_{j=1}^{K}\exp\!\left(-(S_{a,j}-S_{a,\min})/\lambda\right)}.
$$

Here $S_{a,\min}$ is the lowest sampled score for anchor $a$, $\lambda>0$ is the weighting temperature, and $j$ indexes that anchor's $K$ samples in the denominator. Use $w_{a,k}$ to form the weighted noise update of $\bar u_{a,t}$, reapply the burst mask, and finally roll out every updated nominal without noise. Compare those actual Bellman objectives across anchors; do not compare weights or the luckiest noisy sample across different horizons.

This direction fits the nonlinear dynamics and parallel hardware better than branch-and-bound. Its limitations are also clear:

- input bounds and exact coast are easy, but state constraints require rejection or penalties and are not certified;
- the full $41\times41$ timing grid is too large to pair with thousands of samples, so use a small anchor set or a Bellman $Q$ model to shortlist anchors;
- GPU benefit comes from many analytic rollouts, not from the small critic network;
- the current Windows lock resolves CPU-only PyTorch, so a CUDA-enabled environment is required;
- the existing IPOPT computation-time feature is invalid for batched MPPI and must be recalibrated;
- the current MPC has zero terminal weight and only energy error active, so MPPI alone will not repair the strategic objective.

If the full path-integral importance correction is omitted, describe the implementation as MPPI-style weighted shooting rather than claiming a canonical MPPI implementation. If minimum implementation complexity matters more than the MPPI label, the cross-entropy method (CEM) is an even simpler batched sampling baseline.

## 9. Lowest-risk execution order

1. Freeze the event definition, make the state Markov, and build a coarse current-MPC transition graph.
2. Solve it by reverse Dijkstra, refine state/action resolution, and use table interpolation first.
3. Distill $Q(s,B,H)$ only if table storage or lookup is a measured problem.
4. Run fixed $(B,H)$ IPOPT candidates concurrently as the minimum-change timing baseline.
5. Validate tensor fourth-order Runge–Kutta (RK4) propagation against NumPy and CasADi, then compare fixed-anchor MPPI with multistart IPOPT.
6. Only then add several $(B,H)$ anchors, terminal $\widehat V$, exact top-candidate refinement, and held-out closed-loop comparison.

Report goal-and-hold success, total Bellman cost and each cost component, completion time, event count, constraint violations, same-state horizon regret, median and 95th-percentile planning time, and variability across MPPI seeds.

The final claim should be “Bellman-optimal on the declared finite abstraction” only after state/action refinement and independent Bellman-residual checks. It remains approximate for the continuous plant because of discretization, interpolation, model mismatch, and local inner optimization.
