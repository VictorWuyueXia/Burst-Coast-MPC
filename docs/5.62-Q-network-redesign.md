# Quick View

This project uses reinforcement learning only to choose the burst-coast timing
action outside MPC. The neural policy does not output torque and does not replace
the CasADi MPC solve.

At replanning state $s_k$, the high-level action is the realized integer pair

\[
a_k=(B_k,H_k),
\]

where $H_k$ is the MPC horizon in simulator steps and $B_k\leq H_k$ is the
active burst length. The logged continuous coordinates \(\bar B\) and \(\bar H\)
are sampling coordinates that map to this discrete action. Deployment evaluates a
deduplicated grid of realized \((B,H)\) pairs and chooses the lowest predicted
cost.

The immediate cost remains unchanged:

\[
c_k = \Delta t_k
    + \sum_i (u_i/u_{\max})^2
    + t_{\mathrm{solve},k}/\Delta t
    + 100\,\mathbb 1_{\mathrm{terminal\ failure}}.
\]

The discount is \(\gamma=1\). The desired critic is the optimal finite-horizon
cost-to-go

\[
Q^*(s_k,a_k)=c_k+\mathbb 1_{\neg d_k}\min_{a'}Q^*(s_{k+1},a').
\]

Time remaining is therefore part of the state. MPC continues to solve the torque
sequence after the critic selects one timing action.

The current physical dataset is:

| Split | Runs | RL transitions | Successes | Failures |
|---|---:|---:|---:|---:|
| `train` | 1,752 | 14,920 | 1,715 | 37 |
| `val` | 220 | 1,860 | 214 | 6 |
| `test` | 220 | 1,875 | 215 | 5 |
| **Total** | **2,192** | **18,655** | **2,144** | **48** |

The short-horizon corpus has 1,201 runs and 16,397 transitions with
`hbar-max=1`. Its folder suffix is `0NP` because the historical config stored
`prediction-horizon-natural-periods=0`; that suffix is metadata, not the semantic
action limit. The long-horizon corpus has 991 runs and 2,258 transitions with
`hbar-max=5` and suffix `5NP`.

## Why Previous Training Failed

1. The two named historical result directories are byte-for-byte identical. The
   directory under `artifacts/model-snapshots` is the original offline snapshot,
   and the directory under `artifacts/inverted_pendulum_frozen` is its frozen
   copy. There is no preserved `online-critic_*` result or online episode corpus
   from which to claim successful online learning.
2. The old critic was trained on 13,783 rows from the obsolete
   `artifacts/MonteCarloData` contract. It used neither the current failure corpus
   nor the current five-period action domain and had no locked test set.
3. The action meaning changed after that snapshot. The old data treated both
   action coordinates as normalized to \([0,1]\) and realized approximately
   \(B=0.5\bar B H\). The current contract uses \(\bar H\) directly in natural
   periods and \(B\approx\bar B H\). The frozen model is therefore not a valid
   warm start for the current action.
4. The old input omitted remaining episode time, unwrapped angle, and constraint
   margin. The same trigonometric state can have a different finite-horizon value
   or a different distance to the \(\pm2\pi\) angle limit.
5. Row-wise MSE fitted the return of the uniform Monte Carlo continuation policy,
   not the cost of continuing with the policy used at deployment. Future random
   actions dominate much of each label, so the action-ranking signal for the
   current action is weak.
6. The model learned the fixed physical weights. They moved from
   \((1,1,1)\) to approximately \((1.099,0.612,0.630)\), improving regression by
   changing the intended objective rather than by learning only strategic value.
7. Offline Q surfaces reused one observed solve time across every candidate,
   while deployment substituted a separate time model. Training diagnostics and
   deployment did not score the same action cost.
8. The online updater, as implemented, creates a new replay buffer for each
   episode, trains on only that episode, and takes a raw minimum over the full
   action grid without an offline-support penalty. This is a direct path to
   optimistic extrapolation and catastrophic forgetting.

The historical snapshot did reduce validation MSE from 608,543 for its physical
baseline to 13,918, but this only shows that a small MLP can regress the old logged
returns. It does not demonstrate correct current action ranking or closed-loop
improvement.

## How To Fix Target Mismatch

The logged Monte Carlo return is not useless. It estimates

\[
Q^{\mu}(s,a)
=\mathbb E[G_k\mid s_k=s,a_k=a,\ a_{j>k}\sim\mu],
\]

where \(\mu\) is the uniform random continuation policy. Greedy action selection
from an accurate \(Q^\mu\) is a legitimate first policy-improvement step, but
\(Q^\mu\neq Q^*\), and the one-action-per-state dataset makes its action ranking
noisy.

Do not fix this by selecting the lowest-return episodes and calling every row in
them optimal. Different episodes visit different states, and taking the minimum of
noisy unrelated histories creates winner's bias.

Use three controlled steps instead:

1. Pretrain on recalculated Monte Carlo returns only to learn state/action scale
   and a stable behavior critic.
2. Replace the Monte Carlo target with a conservative one-step Bellman optimality
   target using twin target critics. This turns the existing transitions into
   fitted policy iteration while guarding against falsely cheap unseen actions.
3. Generate policy-directed trajectories and common-state action branches, append
   only their training records, and repeat policy improvement. These records make
   the continuation policy progressively match the policy being learned.

The preferred additional data is not another large batch of uniformly random full
episodes. It is a smaller set of actions evaluated from the same anchor states,
plus full trajectories generated by the improving policy.

## The New Model Design

Use a twin scalar cost critic with smooth state/action encoders. A recurrent model
is not needed once the state includes unwrapped position and remaining time; the
sequence structure is used through the transition and Bellman target. A
distributional head is also deferred: compute-label contamination should be fixed,
not treated as useful return randomness.

Collapsed model:

```text
state[7]  -> 64 -> 64 -----------+
                                    concat(state, action, state * action)
action[4] -> 32 -> 64 -----------+---------------+
                                                    |
                  +---------------------------------+-------------------+
                  |                                 |                   |
             Q1: 192 -> 128 -> 64 -> 1         immediate: 192 -> 64 -> 1
             Q2: 192 -> 128 -> 64 -> 1         failure:   192 -> 32 -> 1
```

All hidden activations are `SiLU`. `Q1`, `Q2`, and the immediate-cost head use a
positive output in normalized cost units. The failure head emits a logit. The
deployed score is the conservative cost

\[
Q_{\mathrm{deploy}}(s,a)=\max(Q_1(s,a),Q_2(s,a)).
\]

The cost weights remain fixed at the project values. No learned lambda can alter
the objective.

## The Training Steps

1. Make the physical `train`, `val`, and `test` directories the only split source.
   Validate complete ordered trajectories and never rediscover or reshuffle the
   test folders.
2. Reconstruct the full Markov state, calibrate representative single-worker
   compute cost, and rebuild immediate costs and Monte Carlo returns in memory.
   Preserve the raw CSV files.
3. Train the behavior-return baseline on `train`; use `val` for early stopping.
   This is a diagnostic initialization, not the final critic.
4. Train the twin critic with conservative fitted-Q targets, balanced equally
   between the short- and long-horizon corpora. Select the checkpoint using
   validation Bellman error, action-support diagnostics, and fixed closed-loop
   validation cases.
5. Run a common-state action-branch pilot and policy-directed trajectory round.
   Retrain, then repeat only while the validation policy improves.
6. Freeze the complete method. Open `test` once, then run a fixed closed-loop test
   bank against unchanged MPC and historical critic baselines.

# The Details

## Fixed Contract And Notation

### State

The Markov state used by the critic is

\[
s_k=(\theta_k,\omega_k,t_k,m_k),
\]

where \(m_k\) denotes the constraint/goal diagnostics derivable from the live
observation. The network receives the following seven scalar features:

1. \(\sin\theta\);
2. \(\cos\theta\);
3. \(\omega/\omega_{\mathrm{ref}}\), with
   \(\omega_{\mathrm{ref}}=2\sqrt{g/l}\);
4. normalized energy error \((E-E^*)/E^*\);
5. unwrapped \(\theta/\theta_{\max}\);
6. the live constraint margin;
7. remaining fraction
   \((N_{\max}-t_{\mathrm{index}})/N_{\max}\).

The last three features correct concrete aliasing in the old model. For current
artifacts, unwrapped angle and margin are joined from `steps.csv` at each
`start-t-index`; the initial row is reconstructed from the logged initial state.
Future generators must write these values directly into `rl_steps.csv`.

### Action

The action is represented by what MPC actually executes, not by duplicate sampling
coordinates. Let \(H_{\max}\) be the integer horizon for five natural periods.
The four action/context inputs are:

1. realized burst fraction \(B/H\);
2. normalized horizon \(H/H_{\max}\);
3. normalized burst length \(B/H_{\max}\);
4. calibrated compute feature
   \(\log(1+\hat t_{\mathrm{solve}}/\Delta t)\).

The deployment grid may be constructed from \((\bar B,\bar H)\), but duplicate
realized \((B,H)\) pairs are removed before critic evaluation. Candidate axes use
the supported domain \(0.01\leq\bar B\leq1\) and
\(0.01\leq\bar H\leq5\).

### Cost And Terminal Meaning

For every transition, independently reconstruct:

\[
c_k=c_{t,k}+c_{u,k}+c_{c,k}+c_{f,k},
\]

with

\[
c_{t,k}=t_{k+1}-t_k,\qquad
c_{u,k}=\sum_i(u_i/u_{\max})^2,
\]

\[
c_{c,k}=\hat t_{\mathrm{solve},k}/\Delta t,\qquad
c_{f,k}=100\,\mathbb 1_{\mathrm{terminal\ failure}}.
\]

`done=True` identifies the terminal transition but does not identify success.
Success is `goal_reached`; failure is `max_steps_reached`. Outcome comes from the
episode finish record and must agree with the final index.

No reward sign conversion is used in stored artifacts. Lower Q is better.

### Compute-Time Label Problem

The short-horizon solve-time distribution is bounded in the current data: median
0.843 s, 99th percentile 4.516 s, maximum 5.891 s.

The long-horizon records were generated under changing parallel-worker load and
contain operationally confounded measurements:

| Long-horizon solve-time statistic | Value |
|---|---:|
| median | 18.594 s |
| 90th percentile | 169.969 s |
| 99th percentile | 753.234 s |
| maximum | 18,147.5 s |
| runs containing a solve over 60 s | 551 / 991 |
| rows containing a solve over 300 s | 109 |
| rows containing a solve over 3,600 s | 14 |

Because compute cost divides solve time by 0.01 s, the largest immediate cost is
1,814,834 and the largest return is 1,818,818. These numbers can represent a mix
of genuine difficult solves, process contention, and interrupted scheduling. The
current files do not contain enough solver-status and process-time evidence to
separate those causes.

Do not silently clip these labels and do not train the main Q target directly on
them. Build a single-worker calibration set on the deployment machine, record
wall time, process time, solver status, and iteration count, and use repeatability
to distinguish genuine solver stalls from parallel contention. Recompute training
costs with the expected single-worker wall-time model while retaining raw solve
time for audit. A repeatedly reproduced stall remains an expensive action; an
unreproduced parallel delay does not.

The frozen `current-surface-lasso-20260630T184805` model is only a baseline. It was
fit from older mixed artifact roots, uses 5,081 rows, and models solve time from
`H`, `B`, and `BH` with RMSE 0.603 s. It has not been validated on the present
five-period, multiworker corpus.

### Loader Mismatch That Must Be Removed

The current offline loader is not yet compatible with the physical dataset:

- it recursively loads `train`, `val`, and `test` together and then randomly
  creates a new train/validation split;
- it has no locked test path;
- it requires every run to have the same `hbar-max`, so it rejects the two
  behavior-coverage configurations even though plant and cost constants match;
- it treats independent rows as the dataset unit.

The new loader reads each physical split explicitly. `hbar-max` is coverage
metadata, not a plant constant and not a reason to reject a run.

## Correct Treatment Of The Target

### Behavior Return Is An Initialization, Not The Final Label

For the uniform Monte Carlo behavior policy \(\mu\), the current backward return is

\[
G_k^\mu=\sum_{j=k}^{T}c_j,
\qquad
Q^\mu(s,a)=\mathbb E[G_k^\mu\mid s_k=s,a_k=a].
\]

This target is internally valid after compute-cost recalibration. It should be
used to initialize the encoders and to provide a behavior-critic baseline. It
must not remain a fixed competing objective during final optimality training,
because that would pull the critic back toward random continuation values.

### Conservative Fitted-Q Target

Maintain online critics \(Q_1,Q_2\) and slowly updated target critics
\(Q_1^-,Q_2^-\). For a nonterminal transition, define the conservative cost score

\[
Q_C^-(s',a)=\max(Q_1^-(s',a),Q_2^-(s',a)),
\]

choose

\[
a^*=\arg\min_{a\in\mathcal A_{\mathrm{unique}}}Q_C^-(s',a),
\]

and train to

\[
y=c_{\mathrm{calibrated}}
 +(1-d)Q_C^-(s',a^*).
\]

The maximum between critics is deliberate for a cost formulation: it counters the
falsely low estimate that a minimum action selector would otherwise exploit. The
target action grid is deduplicated by realized \((B,H)\).

Use one-step backups for the existing off-policy data. Naive three- or five-step
targets would include several random behavior actions before bootstrapping and
would reintroduce the same continuation-policy mismatch. Multi-step targets are
allowed only for trajectories generated by the current target policy or with a
derived off-policy correction.

### Cost-Oriented Conservative Penalty

For each critic, use the cost-oriented CQL term

\[
\mathcal L_{\mathrm{CQL},i}
=\mathbb E[Q_i(s,a_{\mathrm{data}})]
 -\mathbb E[\operatorname{softmin}_{a\in\mathcal A}Q_i(s,a)].
\]

Minimizing this term raises unsupported actions that appear artificially cheap and
anchors logged actions. Use normalized costs and soft-min temperature 1. Select
\(\alpha_{\mathrm{CQL}}\in\{0.01,0.1,1.0\}\) on validation policy diagnostics;
do not tune it on test.

## Model Specification

### Torch-Style Structure

```python
state_encoder = Sequential(
    Linear(7, 64), SiLU(),
    Linear(64, 64), SiLU(),
)

action_encoder = Sequential(
    Linear(4, 32), SiLU(),
    Linear(32, 64), SiLU(),
)

pair = concat(state_embedding, action_embedding,
              state_embedding * action_embedding)  # 192

q1 = Sequential(Linear(192, 128), SiLU(),
                Linear(128, 64), SiLU(), Linear(64, 1))
q2 = Sequential(Linear(192, 128), SiLU(),
                Linear(128, 64), SiLU(), Linear(64, 1))
immediate = Sequential(Linear(192, 64), SiLU(), Linear(64, 1))
failure = Sequential(Linear(192, 32), SiLU(), Linear(32, 1))
```

Apply `softplus` to the two Q outputs and the immediate-cost output after scaling.
The failure output remains a logit. Fit every input mean and standard deviation on
`train` only.

This model is intentionally small. The separate state/action encoders make action
ranking explicit, the multiplicative interaction represents phase-dependent
action effects, `SiLU` gives smoother grid surfaces than the old ReLU network, and
twin heads expose optimistic extrapolation. No actor is needed because deployment
already performs a batched finite-grid minimization.

### Loss

Let \(s_Q\) be the median positive recalculated Monte Carlo return in `train`.
Divide immediate costs, returns, and Bellman targets by \(s_Q\); do not take a log,
because logarithms break additive Bellman structure.

The fitted-Q loss is

\[
\mathcal L=
\operatorname{Huber}(Q_1,y)
+\operatorname{Huber}(Q_2,y)
+\alpha_{\mathrm{CQL}}(\mathcal L_{\mathrm{CQL},1}
                      +\mathcal L_{\mathrm{CQL},2})
+0.25\operatorname{Huber}(\hat c,c)
+0.1\operatorname{BCE}_{\mathrm{weighted}}(\hat p_f,f).
\]

The auxiliary heads regularize physically meaningful information but never add a
new deployment penalty. Failure cost is already present in Q.

### Sampling And Optimization

Construct each batch hierarchically:

1. sample short- and long-horizon source with equal probability;
2. sample a trajectory uniformly within that source;
3. sample one transition uniformly within that trajectory.

This prevents the 16,397 short-horizon rows from overwhelming the 2,258
long-horizon rows and prevents long trajectories from counting as many independent
experiments.

Use fixed initial optimizer settings:

- AdamW, learning rate \(3\times10^{-4}\), weight decay \(10^{-5}\);
- batch size 256 transitions;
- gradient norm limit 5;
- target-network Polyak rate 0.005;
- at most 300 epochs with validation patience 25;
- save and export the best validation checkpoint, never the final epoch by default.

The behavior pretraining pass uses Huber loss to recalculated \(G^\mu\) for at most
50 epochs with patience 10. Fitted-Q training then disables the Monte Carlo
regression loss.

## New Data Requirements

### Mandatory Compute Calibration

Before final Q training, create a single-worker solve-time calibration run on the
deployment workstation. The fixed pilot contains 1,728 solves:

- select 64 train states, 32 from each source, balanced by energy quartile and
  remaining-time quartile;
- evaluate the nine actions induced by
  \(\bar B\in\{0.10,0.50,1.00\}\) and
  \(\bar H\in\{0.10,1.00,5.00\}\) three times per state;
- record wall solve time, process solve time, solver status, iteration count,
  realized \((B,H)\), and state features;
- fit on two repeats and validate on the third;
- preserve repeated stalls as real high compute cost and replace unrepeated
  scheduling delays with expected single-worker time.

The raw Monte Carlo files remain unchanged. The training snapshot records the
calibration artifact hash and both raw and recalculated cost statistics.

### Common-State Action Branches

Uniform full trajectories almost never evaluate two actions from the same state.
The preferred counterfactual dataset is a one-step branch set:

- choose 128 anchor states from `train`, with 64 from each source and equal
  coverage across energy and remaining-time quartiles;
- evaluate the 25 realized actions induced by
  \(\bar B\in\{0.05,0.25,0.50,0.75,1.00\}\) and
  \(\bar H\in\{0.05,0.50,1.00,3.00,5.00\}\);
- restore the same complete simulator state before every candidate;
- execute exactly one burst-coast segment and save immediate cost components,
  successor state, done/outcome, solver diagnostics, and realized \((B,H)\);
- run with one worker so compute measurements match calibration conditions.

This pilot requires 3,200 candidate segments and directly measures within-state
action effects. It is more useful for action ranking than 3,200 unrelated random
episodes.

Store branches physically under:

```text
artifacts/action-branch-data/train/<anchor-run>/branches.csv
```

No branch data enters `val` or `test`. Validation action regret uses a separately
frozen branch bank generated before architecture selection.

### Policy-Directed Trajectories

After the first conservative fitted-Q model:

1. freeze it as policy \(\pi_r\);
2. generate 256 new full training episodes from the original initial-state
   distribution with 90% conservative-greedy actions and 10% uniform exploration;
3. append those complete folders under `artifacts/montecarlo-data/train` with a
   policy-source field in metadata;
4. retrain using all training transitions and the new one-step targets;
5. stop dataset aggregation after two consecutive rounds without validation
   closed-loop improvement.

Do not select only the best episodes. Their Monte Carlo returns estimate
\(Q^{\pi_r}\) and are used as a behavior anchor for the next policy-improvement
round. The Bellman minimum, not retrospective episode selection, defines the
improved action.

Collect at least 20 reproducible long-horizon failure trajectories in training so
the failure head sees that source. These must come from the declared initial-state
distribution or a separately identified stress stratum; do not disguise targeted
stress cases as ordinary Monte Carlo frequency.

## Ordered Training And Evaluation Procedure

### Data Gate

1. Read physical splits separately.
2. Validate every trajectory invariant and reject loudly on the first invalid run.
3. Reconstruct unwrapped state and all immediate cost components.
4. Apply the frozen compute calibration and recompute returns.
5. Fit feature and cost scales on `train` only.
6. Write a snapshot audit containing run counts, transition counts, outcomes,
   source balance, raw/calibrated solve-time quantiles, and rejected paths.

### Historical Baselines

1. Record the old 6-32-16-1 snapshot metrics without treating it as a compatible
   warm start.
2. Train a new scalar behavior-return MLP on the current contract.
3. Train the new twin architecture only on behavior returns to isolate architecture
   benefit from target benefit.

### Conservative Policy Improvement

1. Initialize the twin model from the new behavior-pretrained encoders.
2. Train one-step conservative fitted Q with target networks.
3. Select CQL strength on `val` only.
4. Require both lower validation Bellman error and lower branch action regret than
   the behavior critic.
5. Reject any checkpoint whose selected-action distribution collapses to one grid
   boundary without matching branch evidence.

### Data Aggregation

1. Run the common-state branch pilot.
2. Add policy-directed full trajectories.
3. Refit compute calibration if solver/hardware conditions changed.
4. Retrain and compare on the same frozen validation cases.
5. Continue only while validation closed-loop cost improves without reducing
   success rate.

### Locked Evaluation

After model structure, loss weights, calibration, action grid, and checkpoint rule
are frozen:

1. evaluate once on the 220 test trajectories;
2. report metrics overall and separately for source, success/failure, remaining
   time, energy region, and action region;
3. report expected-Q MAE/RMSE, one-step Bellman error, branch action regret,
   failure precision-recall, CQL support gap, and action-boundary frequency;
4. run a fixed initial-condition bank with learning disabled;
5. compare unchanged MPC, the historical critic, the current-contract behavior
   critic, fitted Q without CQL, and the complete method;
6. report success rate, exact unchanged episode cost, time to goal, effort,
   calibrated and observed solve time, replans, and solver stalls.

Acceptance requires lower closed-loop cost than the current-contract behavior
critic and unchanged MPC without a lower success rate. Offline MSE alone is not an
acceptance criterion.

- `TwinCostCritic`: owns the two encoders, two Q branches, immediate-cost head,
  failure head, and target-compatible forward pass.

No actor, recurrent network, Lightning `DataModule`, generic replay framework,
compatibility wrapper, or fallback dataset path is planned.

### Planned Functions And Methods

- `load_physical_splits(dataset_root)`: read `train`, `val`, and `test` without
  rediscovery or reshuffling.
- `validate_and_build_trajectories(run_dirs, compute_calibration)`: enforce the
  sequence contract, join dense state diagnostics, and rebuild costs/returns.
- `collate_transitions(records)`: vectorize one balanced training batch.
- `build_optimality_targets(batch, target_critic, action_grid)`: evaluate the
  deduplicated grid and construct conservative one-step targets.
- `TwinCostCritic.forward(state, action)`: return `q1`, `q2`, immediate cost, and
  failure logit.
- `train_and_select(train, val)`: run behavior pretraining, fitted-Q training,
  early stopping, and best-checkpoint export.
- `evaluate_locked(model, split)`: produce split-stratified offline diagnostics
  without changing weights.

These are the complete planned wrappers/helpers. New functions require an explicit
revision of this budget.

### Independent Variables And Parameters

Training tensors are exactly:

- `state`: seven normalized state scalars;
- `action`: four normalized realized-action/compute scalars;
- `cost`: recalculated immediate cost;
- `next_state`: seven successor-state scalars;
- `done`: terminal mask;
- `failure`: terminal-failure label;
- `source`: short/long corpus label used only for balanced sampling and metrics;
- `trajectory_index`: run identity used for hierarchical sampling.

Model/training parameters are exactly:

- state widths `64, 64`;
- action widths `32, 64`;
- Q widths `128, 64` for each twin;
- auxiliary widths `64` and `32`;
- AdamW learning rate `3e-4` and weight decay `1e-5`;
- batch size `256`;
- gradient limit `5`;
- Polyak rate `0.005`;
- CQL candidates `0.01, 0.1, 1.0`;
- behavior-pretraining maximum `50` epochs and patience `10`;
- fitted-Q maximum `300` epochs and patience `25`.

System/runtime values remain hardcoded. Only physical experiment choices belong in
experiment config. Any future architecture expansion must first demonstrate a
specific failure of this design on the frozen validation contract.
