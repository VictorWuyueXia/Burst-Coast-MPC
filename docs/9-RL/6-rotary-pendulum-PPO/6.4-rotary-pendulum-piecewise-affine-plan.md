# Rotary-Pendulum Piecewise-Affine Dynamics Plan

## 1. Goal and boundary

Build a finite, auditable piecewise-affine approximation of the existing nonlinear
RK4 rotary-pendulum transition map. The nonlinear model remains the source of truth
for data generation and final validation. The affine model is intended for later
explicit MPC, mixed-integer MPC, reachability analysis, and cheap parallel prediction.

This stage is a separate dynamics project. It must not modify PPO reward semantics,
replace the current environment silently, or claim global validity outside its declared
state-action domain.

## 2. Reference map and local affine model

Let the physical state and scalar shaft torque be

$$
x=[\theta,\alpha,\omega,\nu]^T,\qquad u=\tau.
$$

The validated nonlinear RK4 transition over $T_s=0.002\,\mathrm{s}$ is

$$
x^+=F(x,u).
$$

For region $r$, choose anchor $(\bar x_r,\bar u_r)$ and compute exact Jacobians of the
symbolic RK4 graph:

$$
A_r=\left.\frac{\partial F}{\partial x}\right|_{(\bar x_r,\bar u_r)},
\qquad
B_r=\left.\frac{\partial F}{\partial u}\right|_{(\bar x_r,\bar u_r)}.
$$

The affine offset is

$$
c_r=F(\bar x_r,\bar u_r)-A_r\bar x_r-B_r\bar u_r,
$$

giving the local discrete model

$$
\boxed{x^+=A_rx+B_ru+c_r.}
$$

$A_r\in\mathbb R^{4\times4}$, $B_r\in\mathbb R^{4\times1}$, and
$c_r\in\mathbb R^4$. They are computed, not learned. Using the RK4 Jacobian rather
than linearizing the continuous ODE and discretizing afterward makes the approximation
target identical to the simulator map.

## 3. Partition variables

The dynamics do not depend explicitly on $\theta$, so do not partition that dimension.
Keep the physical validity condition

$$
|\theta|\leq\theta_{\rm lim}=\pi/2
$$

as a separate domain constraint. Partition only

$$
p=[\widetilde\alpha,\omega,\nu,u]^T,
$$

where $\widetilde\alpha=\operatorname{wrap}(\alpha)\in[-\pi,\pi)$ is used for region
selection. The affine prediction uses the angle lift nearest the region anchor,

$$
\alpha_r=\bar\alpha_r+
\operatorname{wrap}(\alpha-\bar\alpha_r),
$$

so the model remains periodic while the simulator continues to store unwrapped angle.

The first proof-of-concept grid is:

| Variable | Bounds | Intervals | Construction |
|---|---:|---:|---|
| $\widetilde\alpha$ | $[-\pi,\pi)$ | 12 | uniform phase sectors |
| $\omega/\omega_E$ | $[-1,1]$ | 3 | edges $[-1,-0.25,0.25,1]$ |
| $\nu/\nu_E$ | $[-1,1]$ | 5 | edges $[-1,-0.5,-0.15,0.15,0.5,1]$ |
| $u/\tau_{\max}$ | $[-1,1]$ | 3 | edges $[-1,-1/3,1/3,1]$ |

$\omega_E=(\pi/2)\omega_n$ and $\nu_E=2\sqrt{G/J_p}$ are the same derived physical
scales used by PPO. The Cartesian product contains $12\times3\times5\times3=540$
regions. Each anchor is the midpoint of its interval. This is small enough for batched
matrix evaluation and detailed auditing while resolving angle, coupled velocity, and
finite-input RK4 nonlinearities.

States outside the declared velocity or arm domain are invalid for the PWA model and
must raise a domain error. There is no implicit clipping, extrapolation, or nonlinear
fallback. Periodic angle wrapping is part of the declared coordinate map, not fallback
behavior.

## 4. Deterministic region ownership

Use half-open intervals for every internal boundary and close only the final interval.
For example, interval $j$ owns

$$
[b_j,b_{j+1})
$$

except the last interval, which owns its upper edge. The periodic angle value $\pi$ is
mapped to $-\pi$. This gives every admissible state-action point exactly one region.

Store integer multi-index

$$
i_r=(i_\alpha,i_\omega,i_\nu,i_u)
$$

and flattened stable region identifier

$$
r=(((i_\alpha N_\omega+i_\omega)N_\nu+i_\nu)N_u+i_u).
$$

$N_\omega=3$, $N_\nu=5$, and $N_u=3$ are configured interval counts. Stable indexing
is required so exported matrices, audit rows, and later MPC binaries agree.

## 5. Planned implementation budget

### Objects

- `PWAConfig`: angle count plus explicit normalized velocity and torque edges, audit
  sample count, rollout length, seed, and error thresholds.
- `AffineRegion`: immutable region identifier, lower/upper bounds, anchor, $A_r$, $B_r$,
  and $c_r$.
- `PiecewiseAffineDynamics`: the complete stacked region bank, domain validation,
  vectorized region selection, and batched affine prediction.
- `PWAArtifactWriter`: machine matrices/audit tables and human error figures/summary.

No other data classes, adapters, registries, or abstract model interfaces are planned.

### Functions and methods

- `build_piecewise_affine_dynamics(episode, pwa)`: construct the CasADi RK4 Jacobian
  once, evaluate all 540 preprinted anchors in batches, and return the model.
- `PiecewiseAffineDynamics.select_region(state, torque)`: validate the declared domain
  and return stable vectorized region indices.
- `PiecewiseAffineDynamics.step(state, torque)`: select regions and evaluate stacked
  $A_rx+B_ru+c_r$ without a Python loop over samples.
- `audit_piecewise_affine_dynamics(model, episode, pwa)`: compare one-step, boundary,
  equilibrium, and repeated-rollout behavior against nonlinear RK4.
- `PWAArtifactWriter.finalize(model, audit)`: export all evidence with no runtime logic.

These five operations contain the complete workflow. Region construction and audit
sampling are parallel batched operations; no per-region solver process or thin wrapper
functions are planned.

### Independent variables and parameters

Runtime variables are physical state, wrapped selection angle, lifted prediction angle,
torque, region multi-index, flattened region ID, affine next state, nonlinear next state,
and normalized error. Configurable parameters are only the four partition edge sets,
audit seed/count, rollout length, and explicit acceptance thresholds. Physical scales,
RK4 step, torque limit, and arm limit remain derived or inherited.

Planned files are:

```text
src/rotary_pendulum/configs/pwa.yaml
src/rotary_pendulum/environment/piecewise_affine.py
src/rotary_pendulum/utils/config_schema.py
src/rotary_pendulum/utils/pwa_artifacts.py
tests/test_rotary_piecewise_affine.py
```

Each new logic file should remain between approximately 80 and 280 lines. The existing
nonlinear dynamics and environment files remain unchanged.

## 6. Development stages and milestones

### Stage 0: symbolic derivative audit

Build one CasADi function returning $F$, $A$, and $B$. Compare $A$ and $B$ with centered
finite differences at 100 seeded interior points.

Validation procedure:

1. sample points at least $10^{-5}$ of a region width away from boundaries;
2. scale state perturbations by $[\theta_{\rm lim},\pi,\omega_E,\nu_E]$;
3. scale torque perturbation by $\tau_{\max}$;
4. report absolute and normalized Jacobian errors.

Success flag: maximum normalized Jacobian error below $10^{-6}$ and all outputs finite.

### Stage 1: complete region bank

Precompute every anchor and affine matrix. Test every lower edge, interior boundary, upper
edge, and the $-\pi/\pi$ periodic seam.

Success flags:

- exactly 540 unique stable region IDs exist;
- every seeded admissible point owns exactly one region;
- all anchors reproduce the nonlinear RK4 map to floating-point tolerance;
- downward and upright zero-input equilibria are preserved by their owning affine model.

### Stage 2: one-step fidelity audit

Use a stratified sample with equal count per region. For scale vector

$$
s_x=[\theta_{\rm lim},\pi,\omega_ET_s,\nu_ET_s]^T,
$$

define component-normalized transition error

$$
e=(F_{\rm PWA}(x,u)-F(x,u))\oslash s_x,
$$

where $\oslash$ is elementwise division. Report per-state RMSE, 95th percentile, maximum,
and region ID of the worst sample.

Initial proof-of-concept success flags are total normalized RMSE below $0.01$, 95th
percentile norm below $0.03$, and maximum norm below $0.10$. These are tunable model
acceptance thresholds, not physical tolerances.

### Stage 3: boundary and rollout audit

Evaluate both adjacent affine models at every internal face to measure prediction jump.
Then run matched nonlinear and PWA rollouts for 250 physics steps under seeded constant,
sinusoidal, and phase-chasing bounded torque sequences.

Success flags:

- 95th percentile normalized boundary jump below $0.03$;
- no region-selection chatter for a stationary boundary point;
- median 250-step terminal normalized error below $0.10$;
- all domain exits are explicit and identify the first invalid state and region face.

If boundary jump alone fails while one-step fidelity passes, the next planned method is
a continuity-constrained affine fit on the same fixed partition. If both fail, refine
only the worst angle/velocity intervals identified by the audit before adding dimensions.

### Stage 4: closed-loop usefulness

Run unchanged torque sequences from the current nonlinear MPC through both predictors.
Then build a separate PWA-MPC experiment without altering the nonlinear controller.

Success flags:

- accepted nonlinear MPC plans have PWA terminal-cost ordering agreement above 95%;
- PWA-MPC respects torque and arm limits in its own prediction;
- nonlinear replay of PWA-MPC actions reaches the configured goal in at least 90% of
  the exact same seeded validation cases used for the nonlinear controller;
- prediction speedup and memory footprint are reported rather than assumed.

## 7. Artifact contract

Machine-readable data belong in `machine/`:

- resolved PWA and physical configuration;
- `regions.npz` with bounds, anchors, $A$, $B$, and $c$ arrays;
- `one_step_errors.csv`, `boundary_errors.csv`, and `rollout_errors.csv`;
- summary JSON containing thresholds and pass/fail flags.

Human-readable outputs belong in `human/`:

- error distribution by state component;
- worst-region phase/velocity heat map;
- matched nonlinear/PWA rollout traces;
- `interpretation_summary.md` stating whether the model is adequate and which regions
  require refinement.

This separation makes the approximation reproducible by code while keeping the main
judgment shallow and readable.

## 8. Explicit non-goals

The first implementation will not learn region boundaries, fit neural residuals, add
binary MPC variables, replace nonlinear plant rollouts, extrapolate beyond the certified
domain, or jointly tune PPO and PWA models. It establishes an auditable affine dynamics
bank first; optimization methods consume that bank only after its fidelity flags pass.
