# JAX Rotary-Pendulum Environment: Interpretation Summary

The planned pure JAX environment is now implemented beside the unchanged NumPy/CasADi benchmark. It provides the same four-state nonlinear plant, a raw batched and differentiable 20 ms RK4 transition, continuous reset sampling, five-step action holds, and the agreed success, arm-limit, and timeout semantics. Reward design, RL training, local linearization, and controller replacement remain intentionally outside this phase.

The measured validation gates pass on both CPU float64 and one NVIDIA L40S in float32. Across 12,288 state/action cases, the 100 ms transition differs from the 2 ms NumPy reference by at most 0.000096 rad in angle and 0.0027 rad/s in rate, comfortably inside the planned 0.02 rad and 0.5 rad/s limits. The sampled boundary search found no arm excursion that crossed and returned between adjacent 20 ms observations. All 30,000 seeded resets stayed inside their declared supports and the arm boundary.

The functional episode tests cover reset replay, goal dwell, event precedence, clipping, terminal idempotence, timeout, JIT, VMAP, scan, and state/input Jacobians. Random-action rollouts are diagnostic rather than a controller result: all 270 random-torque episodes eventually violated the arm limit, while all 30 zero-torque episodes timed out and none succeeded. This confirms that the environment exposes failures correctly; it does not imply anything about a trained policy.

One L40S completed the 8,192-episode benchmark about 257 times faster than the CPU measurement and sustained a recorded 97% utilization peak on GPU 0 while GPUs 1–7 remained idle. The largest 65,536-episode batch passed without running out of memory. JAX reported about 110 MiB peak allocator use, while `nvidia-smi` recorded about 34.5 GiB reserved by JAX's default preallocation policy; shared-server runs may choose an explicit memory policy later.
