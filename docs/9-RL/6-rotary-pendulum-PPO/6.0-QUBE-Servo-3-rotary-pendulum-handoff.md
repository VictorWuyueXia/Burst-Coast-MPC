# QUBE Servo 3 Rotary Pendulum Benchmark Handoff

**Scenario:** three-dimensional rotary inverted pendulum

**Target package:** `src/rotary_pendulum/`

**Project:** burst-coast MPC

**Prepared:** 2026-07-24
**Official resource snapshot:** Quanser Academic Resources commit [`e8a8a8d`](https://github.com/quanser/Quanser_Academic_Resources/tree/e8a8a8dec138cb6b3203c5cc479c9acc75d55b07)

## 1. Repository decision

The QUBE Servo 3 rotary pendulum is the next deterministic benchmark after
`inverted_pendulum/`. The device moves in three-dimensional space, but its
minimal mechanical model has two generalized coordinates, four states, and one
actuator.

The benchmark contract is:

- nonlinear Furuta-pendulum mechanics;
- state \(x=[\theta,\alpha,\omega,\nu]^T\);
- scalar shaft torque input \(u=\tau\);
- one optimized continuous signed torque prefix;
- one exact zero-torque coast suffix;
- RK4 prediction and single-shooting MPC;
- explicit enumeration of fixed burst/coast splits;
- all physical dimensions, specifications, timing, constraints, and experiment
  choices owned by package configuration;
- no process noise, measurement noise, model mismatch, RL, or training behavior.

The complete mathematical definition is in
[`6.1-rotary-pendulum-MPC-formulation.md`](6.1-rotary-pendulum-MPC-formulation.md).

## 2. Reconciliation of the supplied handoffs

The supplied handoffs describe two related, but physically different, input
models:

| Handoff | Input | Coast meaning |
|---|---|---|
| Three-dimensional dynamics handoff | shaft torque \(\tau\) | \(\tau=0\) |
| Hardware engineering handoff | motor voltage \(v\) | \(v=0\), including back-EMF braking |

The repository benchmark uses the **shaft-torque model** because this preserves
the plant and coast semantics of the existing torque-driven
`inverted_pendulum/` package. The voltage model remains a hardware-realization
boundary only.

These modes must never be conflated. Under the quasi-steady motor model,

\[
\tau_m
=\frac{k_t}{R_m}v-\frac{k_tk_m}{R_m}\omega.
\]

Thus, \(v=0\) produces electromagnetic braking, while \(\tau=0\) is a true
mechanical coast. Hardware use requires back-EMF compensation or a verified
inner torque loop.

## 3. Coordinates and task

Use the inertial frame

\[
\mathcal F_I=\{O,\mathbf e_x,\mathbf e_y,\mathbf e_z\},
\qquad
\mathbf g=-g\mathbf e_z.
\]

The generalized coordinates are

\[
q=
\begin{bmatrix}
\theta\\
\alpha
\end{bmatrix}
\in S^1\times S^1,
\]

where:

| Symbol | Meaning |
|---:|---|
| \(\theta\) | unwrapped rotary-arm angle |
| \(\alpha\) | unwrapped pendulum angle, zero downward |
| \(\omega=\dot\theta\) | rotary-arm angular velocity |
| \(\nu=\dot\alpha\) | pendulum angular velocity |
| \(\beta=\operatorname{wrap}(\alpha-\pi)\) | upright pendulum error |

The continuous state and goal are

\[
x=
\begin{bmatrix}
\theta&\alpha&\omega&\nu
\end{bmatrix}^{T},
\qquad
x^\star=
\begin{bmatrix}
0&\pi&0&0
\end{bmatrix}^{T}.
\]

The dynamics integrate unwrapped \(\theta\) and \(\alpha\). Wrapping is used only
for periodic pendulum error and goal evaluation. A physical cable-travel limit
acts on unwrapped \(\theta\) and is not periodic.

## 4. Three-dimensional geometry

Define the rotary basis

\[
\mathbf e_r(\theta)=
\begin{bmatrix}
\cos\theta\\
\sin\theta\\
0
\end{bmatrix},
\qquad
\mathbf e_t(\theta)=
\begin{bmatrix}
-\sin\theta\\
\cos\theta\\
0
\end{bmatrix}.
\]

For arm length \(r\), pendulum pivot-to-tip length \(L_p\), and pendulum
pivot-to-center distance \(l\),

\[
\mathbf p_A=r\mathbf e_r,
\]

\[
\mathbf d(\theta,\alpha)
=\sin\alpha\,\mathbf e_t-\cos\alpha\,\mathbf e_z,
\]

\[
\mathbf p_P=r\mathbf e_r+l\mathbf d,
\qquad
\mathbf p_{\mathrm{tip}}=r\mathbf e_r+L_p\mathbf d.
\]

The package must reconstruct these Cartesian quantities algebraically. It must
not integrate Cartesian positions as independent states.

## 5. Configuration ownership and official defaults

The future package configuration is the single source of numerical plant truth.
The dynamics and MPC equations contain no embedded dimensions or device
specifications.

The default model uses the Quanser manual/courseware parameterization that
reproduces the published rotary-pendulum linear model:

| Quantity | Symbol | Default | Provenance |
|---|---:|---:|---|
| Gravity | \(g\) | \(9.81\ {\rm m/s^2}\) | Quanser model convention |
| Rotary-arm mass | \(m_r\) | \(0.095\ {\rm kg}\) | Quanser nominal |
| Motor axis to pendulum pivot | \(r\) | \(0.085\ {\rm m}\) | Quanser nominal |
| Pendulum mass | \(m_p\) | \(0.024\ {\rm kg}\) | Quanser nominal |
| Pendulum model length | \(L_p\) | \(0.129\ {\rm m}\) | manual/courseware model |
| Pendulum center distance | \(l\) | \(L_p/2=0.0645\ {\rm m}\) | derived uniform-rod model |
| Rotary damping | \(b_r\) | \(1.0\times10^{-3}\ {\rm N\,m\,s/rad}\) | courseware initialization |
| Pendulum damping | \(b_p\) | \(5.0\times10^{-5}\ {\rm N\,m\,s/rad}\) | courseware initialization |
| Torque limit | \(\tau_{\max}\) | \(0.0204\ {\rm N\,m}\) | rated motor torque |
| Integration/control step | \(T_s\) | \(0.002\ {\rm s}\) | official 500 Hz interface |

The current Quanser product page lists a \(0.095\ {\rm m}\) pivot-to-tip
pendulum length, while the manual/courseware model uses \(0.129\ {\rm m}\).
The benchmark default remains \(0.129\ {\rm m}\) so its nominal dynamics match
the official model. Hardware deployment requires measuring the delivered
attachment and selecting an explicit hardware configuration.

The future config stores \(L_p\); the benchmark derives \(l=L_p/2\) rather
than maintaining two independently editable rod dimensions.

The default torque limit is a deterministic benchmark choice based on the
official rated motor torque. It is not a hardware burst-current approval and it
must not be replaced by the \(0.097\ {\rm N\,m}\) stall torque.

Derived quantities are computed from the configured primitives:

\[
J_a=\frac{m_rr^2}{3},
\qquad
J_p=\frac{m_pL_p^2}{3},
\qquad
J_\theta=J_a+m_pr^2,
\]

\[
C=m_prl,
\qquad
G=m_pgl.
\]

The nominal derived values are

\[
J_\theta=4.0219167\times10^{-4}\ {\rm kg\,m^2},
\]

\[
J_p=1.33128\times10^{-4}\ {\rm kg\,m^2},
\qquad
C=1.3158\times10^{-4}\ {\rm kg\,m^2},
\]

\[
G=0.01518588\ {\rm J}.
\]

The \(m_pr^2\) translation term is required to match Quanser's published
linear model. Motor and hub inertias are not added silently to this nominal
benchmark.

## 6. Mechanical model

The nonlinear dynamics use

\[
M(\alpha)\ddot q+h(q,\dot q)+D\dot q=B_\tau\tau,
\]

\[
M(\alpha)=
\begin{bmatrix}
J_\theta+J_p\sin^2\alpha&C\cos\alpha\\
C\cos\alpha&J_p
\end{bmatrix},
\qquad
B_\tau=
\begin{bmatrix}
1\\
0
\end{bmatrix},
\]

\[
h=
\begin{bmatrix}
2J_p\sin\alpha\cos\alpha\,\omega\nu-C\sin\alpha\,\nu^2\\
-J_p\sin\alpha\cos\alpha\,\omega^2+G\sin\alpha
\end{bmatrix},
\qquad
D=
\begin{bmatrix}
b_r&0\\
0&b_p
\end{bmatrix}.
\]

The mass matrix is admissible only when

\[
J_p>0,
\qquad
J_\theta J_p-C^2>0.
\]

The mechanical energy is

\[
\begin{aligned}
E(x)={}&
\frac12\left(J_\theta+J_p\sin^2\alpha\right)\omega^2
+C\cos\alpha\,\omega\nu\\
&+\frac12J_p\nu^2+G(1-\cos\alpha),
\end{aligned}
\]

with upright target energy \(E^\star=2G\). Its exact power balance is

\[
\dot E=\tau\omega-b_r\omega^2-b_p\nu^2.
\]

This identity defines the intended passive-coast behavior.

## 7. MPC inheritance

The rotary benchmark carries forward the current inverted-pendulum MPC choices:

| Existing choice | Rotary-pendulum use |
|---|---|
| deterministic nonlinear plant | coupled Furuta dynamics |
| fixed-step RK4 | same configured model in simulation and MPC |
| torque decisions | shaft torque at the rotary axis |
| single shooting | only burst torques are decision variables |
| explicit split enumeration | \(\lambda\in\{0.1,0.2,0.3\}\) |
| five natural-period horizon | five coupled passive periods |
| zero-input coast | exact \(\tau=0\) suffix |
| normalized energy error | coupled mechanical energy |
| torque slew regularization | normalized by \(\tau_{\max}\) |

The baseline cost is

\[
J=
\sum_{k=0}^{H-1}e_E(x_k)^2
+10^{-3}\sum_{k=0}^{B-1}
\left(
\frac{\tau_k-\tau_{k-1}}{\tau_{\max}}
\right)^2,
\]

\[
e_E(x)=\frac{E(x)-E^\star}{E^\star}.
\]

This is deliberately the same energy-first baseline as the live
`inverted_pendulum` solver. The rotary goal test additionally requires the arm,
pendulum, and both angular velocities to be near the upright target.

## 8. Package boundary

The implementation target remains shallow:

```text
src/rotary_pendulum/
    configs/
    environment/
    mpc/
    visualization/
```

The package mirrors the useful ownership boundaries of `inverted_pendulum/`
without copying its RL or training directories. No compatibility wrapper,
hardware driver, voltage plant, fallback controller, CLI mode, RL policy, or
training script belongs to this benchmark definition.

## 9. Acceptance contract

The benchmark is mathematically consistent when:

1. the 3D kinematics agree with finite differences;
2. \(M(\alpha)\) is symmetric positive definite over a full revolution;
3. analytic and numerical equilibrium linearizations agree;
4. lossless zero-torque trajectories conserve mechanical energy;
5. damped zero-torque trajectories satisfy \(\dot E\le0\);
6. every MPC plan contains one torque prefix and one exact zero-torque suffix;
7. MPC and environment propagation use the same configuration and RK4 map;
8. the complete coast suffix is included in cost and constraint evaluation;
9. upright completion is reported as goal arrival, not as a zero-torque
   invariant-set guarantee.
