# 基于谱系重采样与不确定性可视化的航天器轨迹优化

## 总体判断

你的想法有明确的已有学术邻近方向，但完整组合仍有研究空间。相近方向包括航天器不确定性轨迹优化、采样型 MPC，例如 MPPI 和 VIMPC、序贯蒙特卡洛、加权集合方法、轨迹剪枝与复制、以及基于时序逻辑的任务评分。

目前已有工作分别覆盖了其中若干部分，例如随机小天体侦察、不确定性鲁棒交会、漂移安全机会约束交会、机器学习辅助交会优化、地月空间近距离操作中的元强化学习，以及将形式逻辑代价用于轨迹采样的非航天控制方法。但我没有看到一篇近期航天器论文同时包含以下四点：

1. 基于策略驱动的大批量非线性天体动力学 rollout；
2. 在线剪枝与复制形成轨迹谱系；
3. 用形式化任务逻辑作为选择信号；
4. 用不确定性渲染展示轨迹族演化与可行性。

因此，机制本身不能作为主要创新点。低分粒子淘汰、高分粒子复制，会被审稿人直接联想到 CEM、MPPI、粒子滤波重采样、加权集合 splitting 与 pruning。真正可能成立的创新点应当是：

**面向航天任务语义的谱系化路径集合搜索方法。**

该方法把每条轨迹视为路径分布中的一个分支，用形式任务逻辑评分，用显式多样性管理避免早熟收敛，并通过可视化展示可行轨迹族、近优分支和失败原因。

## 相关工作图谱

航天器领域已有大量不确定性轨迹优化工作。近期研究包括漂移安全交会中的机会约束顺序凸优化、不确定性约束交会中的随机反馈控制与微分动态规划、结合协方差分析的鲁棒轨迹优化、小天体表面覆盖任务中的轨迹重复细化，以及面向自主飞掠的小天体侦察轨迹设计。这些工作说明问题背景及时，但主要仍是直接优化或不确定性传播，不是大规模轨迹谱系重采样。

学习型航天器制导也在快速发展。例如 Autonomous Rendezvous Transformer 用 Transformer warm start 顺序凸优化，而不是直接替代优化器。地月空间近距离操作研究则使用 LSTM 策略并进行蒙特卡洛鲁棒性评估。相关综述也指出，高保真仿真与可验证性仍是 RL 航天应用的瓶颈。你的谱系搜索与渲染方法可以被定位为一种验证辅助机制，而不仅是优化器。

算法层面最接近的是采样控制和路径采样。CEM、MPPI 和路径积分控制属于同一类思想。近期 MPPI 理论工作讨论了随机和确定性情形下的最优性与次优性，也有研究把 MPPI 表述为自由能目标上的预条件梯度下降。与剪枝复制最相近的是 VIMPC 中的 Resampling Based Rollout，其灵感来自粒子滤波，用 rollout 中的重采样减少零权重样本浪费。加权集合方法也周期性地剪枝、复制轨迹，并调整权重，这与原始设想非常接近。

任务评分方面，已有工作使用 Signal Temporal Logic 代价做轨迹规划，也有工作研究随机环境下 STL 策略的时间鲁棒性。RLRom 类方法表明，STL 公式可以在线监测并转化为定量满足度，用作观测或奖励组成。航天领域也存在卫星任务规划中的 STL 应用，但更多停留在任务调度和指向层面，不是闭环非线性天体动力学 rollout 的轨迹族重采样。

## 可成立的创新方向

如果直接表述为“复制好轨迹、删除坏轨迹的新优化器”，创新性不够。更合适的表述是：

**一种面向非线性航天器动力学的语义引导加权路径搜索方法，具有显式轨迹谱系和可行解档案。**

较可信的创新轴有四个：

1. **任务语义驱动选择。**  
   使用 STL、MITL 或类似在线 monitor，让选择压力来自可解释任务逻辑，而不是人工调参的单一奖励函数。

2. **谱系化重采样。**  
   根据 robustness to go、可行裕度、时间窗口进展等中间指标进行重采样，而不是只看终端代价。

3. **多保真度天体动力学。**  
   大部分粒子在低成本模型中传播，精英轨迹再用高保真模型或协方差修正重新评分。

4. **验证导向可视化。**  
   不只显示最优轨迹，还显示近优轨迹族、失败分支、谱系树和不确定性管，从而支持可解释性和操作员信任。

一个更适合论文的表述是：

**本文提出一种在线航天器轨迹路径集合搜索方法。该方法通过形式任务逻辑引导路径分布重采样，在非线性时变受扰天体动力学下自适应分配计算资源，并通过轨迹谱系与不确定性渲染解释可行轨迹的形成过程。**

建议避免把硬阈值淘汰作为核心机制。更稳妥的做法是使用归一化权重和有效样本数触发重采样。硬阈值容易过早破坏多样性，可以作为后期可行集形成后的精英搜索模式，而不是主算法。

## 建议的算法表述

直观上，每个粒子不是“当前真实状态的估计”，而是一个“候选未来”。动力学和噪声负责让未来分叉，任务逻辑负责筛选未来，重采样负责把计算量分配给更有希望的轨迹族，同时保留探索多样性。

可以写成：

$$
u_k^{(i)}=\pi_\phi(x_k^{(i)},m_k^{(i)}),
$$

$$
x_{k+1}^{(i)} = f_k(x_k^{(i)},u_k^{(i)})+G_k(x_k^{(i)})\xi_k^{(i)}.
$$

其中，$x_k^{(i)}$ 是第 $i$ 个粒子在控制步 $k$ 的状态，$u_k^{(i)}$ 是由 RL 策略、MPC 或轻量控制律给出的控制量，$m_k^{(i)}$ 是可选策略记忆，$f_k$ 是一个控制区间内的时变非线性动力学映射，$\xi_k^{(i)}$ 是扰动，$G_k$ 是扰动输入矩阵。

任务评分可写为：

$$
s_k^{(i)} =
s_{k-1}^{(i)}
+r_k^{\mathrm{mission}}
-\lambda c_k^{\mathrm{viol}}
+\mu \rho_k(\varphi,\tau_{0:k}^{(i)}).
$$

其中，$s_k^{(i)}$ 是累计评分，$r_k^{\mathrm{mission}}$ 是普通任务奖励，$c_k^{\mathrm{viol}}$ 是约束违反惩罚，$\rho_k(\varphi,\tau_{0:k}^{(i)})$ 是轨迹前缀 $\tau_{0:k}^{(i)}$ 对任务逻辑公式 $\varphi$ 的在线鲁棒满足度，$\lambda$ 和 $\mu$ 是权重。

将评分转为权重：

$$
w_k^{(i)}=
\frac{\exp(\beta s_k^{(i)})}
{\sum_j \exp(\beta s_k^{(j)})}.
$$

有效样本数为：

$$
N_{\mathrm{eff}} =
\frac{1}{\sum_i (w_k^{(i)})^2}.
$$

当

$$
N_{\mathrm{eff}} < \eta N
$$

时触发重采样，其中 $N$ 是粒子数，$\eta$ 是阈值比例。这样比硬淘汰更稳定，也更接近现代路径积分控制和序贯重采样方法。

需要把搜索群体和解档案分开。搜索群体用于探索，解档案用于决策。建议维护一个长期 archive，保存满足逻辑公式或超过可行阈值的轨迹。排序方式建议采用词典序：

1. 可行性；
2. 逻辑鲁棒度；
3. 任务完成时间；
4. 燃料、风险或安全裕度。

不要在每次复制时拷贝完整历史。每个控制步只存储状态、动作和父索引 $a_k^{(i)}$。最终轨迹通过 ancestry chain 回溯重构。这样既节省内存，又天然得到轨迹谱系。

可视化中不建议只用亮度。可以用亮度或透明度表示权重或得分百分位，用颜色表示任务模式或可行性，用管状或带状结构表示精英轨迹族的不确定性。

## 计算与实现建议

最快可用路线不是从完整 C++ 项目开始，而是使用 Python 组织实验流程，用编译后的传播核心承担动力学计算。

首选路线：

**Python orchestration + heyoka.py 动力学传播 + NumPy 数据结构 + 可选 Numba kernel。**

如果天体动力学模型是主要计算瓶颈，`heyoka.py` 是优先选择。它基于 Taylor 方法、自动微分和 LLVM JIT，支持非自治系统、稠密输出、事件检测、变分方程、SIMD batch、ensemble simulation 和自动并行。对于需要 ODE45 或更高精度的航天动力学传播，它是低开发成本下很强的选择。

低摩擦替代路线：

**Numba + numbalsoda。**

Numba 可以编译 Python 循环，支持 CPU 多线程 `prange`，并减少 GIL 影响。`numbalsoda` 提供 LSODA 和 DOP853，可从 Numba 编译代码内部调用。该路线适合快速实现自适应积分，又不需要马上写 C++。`fastmath` 只有在验证不会破坏轨道精度后再使用。

SciPy 的 `solve_ivp` 建议只作为正确性基线。它支持 RK45、DOP853、Radau、BDF 和 LSODA，但大规模粒子并行时 Python 调度成本较高。`scikits.odes` 和 CVODE 可作为更成熟的 CPU 中间路线。CVODE 提供非刚性 Adams 方法、刚性 BDF 方法、误差控制和 root finding。

如果后期需要 GPU 或可微仿真，可以考虑 JAX + Diffrax。Diffrax 支持 vmap、Tsit5、Dopri5、Dopri8、稠密解和多类求解器。但 JAX 默认使用 32 位浮点，航天问题中必须启用 64 位。还要接受 JIT 编译和静态 shape 限制。它不是最低开发成本的第一选择。

## 推荐代码结构

建议模块划分如下：

```text
src/
  dynamics/
    propagator.py        # heyoka 或 numbalsoda 包装
    models.py            # two body, CR3BP, J2, third body 等
  policy/
    nominal_mpc.py       # 单条名义 MPC 或轻量控制律
    rl_policy.py         # 可选 RL 策略
  logic/
    monitor.py           # STL 或 MITL 在线 robustness
    predicates.py        # 到达、避障、覆盖、时间窗口等谓词
  sampler/
    population.py        # 粒子状态、权重、父索引
    resampling.py        # soft resampling, ESS trigger
    archive.py           # 可行轨迹档案
  experiments/
    rendezvous_case.py
    coverage_case.py
  visualization/
    render_points.py
    render_genealogy.py
    render_uncertainty_tube.py
````

数据布局应使用 structure of arrays，而不是每个粒子一个 Python object。典型数组包括：

```text
X[k, i, state_dim]       # 状态
U[k, i, control_dim]     # 控制
score[k, i]              # 累计评分
weight[k, i]             # 归一化权重
parent[k, i]             # 父粒子索引
mode[k, i]               # 任务模式或逻辑状态
```

每个控制区间内部可以用自适应积分，但主存储只保留区间端点和事件时间。需要高分辨率轨迹时，只对 archive 中的精英轨迹重新采样稠密输出。

最需要避免的架构错误是：

**不要在每个时间步为 2000 个粒子分别求解完整非线性 MPC。**

更合理的方式是：用一个名义 MPC 或学习策略给出参考控制，再让粒子围绕该参考控制分叉。否则计算瓶颈会从动力学传播转移到内部优化器。

如果 profiling 显示 Python 侧仍是瓶颈，再把核心 kernel 提升到 C++，用 pybind11 绑定。CasADi、Dymos 和 pykep 更适合作为基线生成器、交叉验证工具或单轨迹优化器，而不适合作为大批量谱系采样的 runtime core。

## 实验与论文策略

建议至少使用两个任务验证：

1. 交会或近距离操作任务；
2. 行星或小天体表面覆盖任务。

可选场景包括漂移安全交会、地月空间近距离操作、小天体特征覆盖或侦察。这些方向已有近期文献，容易建立可信 baseline。

建议对比方法包括：

1. 直接优化 baseline，例如 SCP 或 DDP；
2. 采样 baseline，例如 MPPI 或 CEM，但不使用谱系重采样；
3. 学习策略 baseline，如果使用 RL；
4. 你的语义引导谱系重采样方法。

主要指标应包括：

1. 可行率；
2. 首次找到可行轨迹的时间；
3. 最佳可行逻辑鲁棒度；
4. 燃料消耗；
5. 安全裕度；
6. 每个控制步 wall clock 时间。

次要指标包括：

1. 最终轨迹多样性；
2. ancestry entropy；
3. effective sample size 随时间变化；
4. archive 改进率；
5. 近优轨迹族数量。

关键 ablation 包括：

1. 终端评分 versus 在线逻辑 robustness；
2. 无重采样 versus 谱系重采样；
3. 硬阈值淘汰 versus soft weighted resampling；
4. 无多保真度复核；
5. 无不确定性可视化；
6. 无谱系 archive。

最可发表的版本不是“很多点加 RL 或 MPC”，而是：

**一种语义引导的航天器路径集合方法，在非线性受扰天体动力学中把计算资源分配给有希望的轨迹族，并通过谱系与不确定性渲染保持搜索过程可解释。**
