# Quick View

Reinforcement learning chooses only the burst-coast timing action. It does not
output torque and does not replace the model predictive control (MPC) solve. The
cost critic is the neural network that predicts total future cost.

At decision state $s_k$, the timing action is

$$
a_k=(B_k,H_k),
$$

where $H_k$ is the MPC prediction horizon in simulator steps and $B_k\leq H_k$ is
the active burst length. The stored coordinates $\bar B$ and $\bar H$ map to this
integer pair. The deterministic policy evaluates each distinct $(B,H)$ pair and
selects the pair with the lowest predicted cost.

The immediate cost remains

$$
c_k = \Delta t_k
    + \sum_i (u_i/u_{\max})^2
    + t_{\mathrm{solve},k}/\Delta t
    + 100\mathbb{1}_{\mathrm{terminal\ failure}}.
$$

The discount is $\gamma=1$. The required critic predicts the total cost from the
current decision until the goal or the fixed simulation-step limit:

$$
Q^*(s_k,a_k) = c_k + \mathbb{1}_{\neg d_k} \min_{a'} Q^*(s_{k+1},a').
$$

MPC still computes the torque sequence after the critic selects one timing action.

| `train`   | 1,752           | 14,920      | 1,715     | 37       |
| `val`     | 220             | 1,860       | 214       | 6        |

| **Total** | **2,192**       | **18,655**  | **2,144** | **48**   |

The short-horizon data group contains 1,201 simulation runs and 16,397 transitions with
`hbar-max=1`. Its folder suffix is `0NP` because an earlier configuration stored
`prediction-horizon-natural-periods=0`; the suffix does not define the action
range. The long-horizon data group contains 991 simulation runs and 2,258 transitions with
`hbar-max=5` and suffix `5NP`.

The following terms have one meaning throughout this document:

- A **simulation run** is one complete simulation from one initial state until
  success or the simulation-step limit. Artifact files call it an `episode`.
- A **transition** is one decision record containing the state, selected action,
  immediate cost, next state, and terminal status.
- A **candidate action** is one possible $(B,H)$ pair evaluated at a state.
- The **behavior policy** is the action-selection rule that generated training
  data. The existing Monte Carlo behavior policy samples actions uniformly.
- The **deterministic policy** selects the candidate action with the lowest
  predicted cost.
- A **training target** is the numerical cost value that the critic is trained to
  predict for one transition.
- A **checkpoint** is a saved critic state from a specific training time.
- A **target critic** is a delayed copy of a critic used only to calculate stable
  training targets.
- A **reference critic** is trained or preserved only for comparison with the new
  critic.
- A **fixed validation set** is data excluded from parameter updates and kept
  unchanged during model selection.
- **Dataset support** means that similar state-action pairs are present in the
  training data.
- **Replay data** are stored transitions sampled again during parameter updates.
- **Model parameters** are the numerical values adjusted during training that
  determine the critic's predictions.
- **Input scaling** subtracts the training-set mean and divides by the training-set
  standard deviation for each input feature.
- A **same-state action comparison** resets the simulator to one saved state before
  evaluating each candidate action.

## Why Previous Training Failed

1. The online critic did not improve. Only checkpoints 1--4 of 128 reached the
   goal under the deterministic policy. Checkpoints 5--128 reached the 30-second
   limit. The final critic selected nearly one-step horizons and failed.

2. A simulation run, called an `episode` in the artifact files, is one complete
   simulation. Exploration means selecting actions probabilistically instead of
   always using the deterministic policy during training data collection. All 127
   recorded online training simulation runs succeeded because exploration sometimes
   selected useful actions that the critic did not select by itself. Therefore,
   success in these exploratory simulation runs measured the critic plus
   exploration, not the deterministic policy. Only 4 of 128 deterministic
   checkpoint evaluations succeeded.

3. The old critic used 13,783 transition records in an earlier data format. Those
   records excluded the current failure records and excluded the current action
   range up to five natural periods. The old training also had no separate test
   set. Therefore, its result does not represent the current dataset or action
   range.

4. The action definition changed. The old data stored both action coordinates in
   $[0,1]$ and used approximately $B=0.5\bar B H$. The current definition uses
   $\bar H$ in natural periods and $B\approx\bar B H$. The old critic therefore
   receives action values with a different meaning and scale and must not be used
   as the initial model for new training.

5. The old state omitted remaining simulation time, unwrapped angle, and constraint
   margin. The required value is the total expected cost before the fixed
   simulation-step limit, so the same physical state can have a different value
   when less time remains. The angle margin is
   $2\pi-|\theta_{\mathrm{unwrapped}}|$; it states how close the pendulum is to the
   configured $\pm2\pi$ angle constraint. Sine and cosine alone do not contain this
   information.

6. Each transition was trained independently against its recorded total future
   cost. That future cost includes later actions selected by the random Monte Carlo
   behavior policy. Consequently, two similar current actions can receive very
   different targets because later random actions differ. The target therefore
   contains more information about later random choices than about the quality of
   the current action. This weakens the critic's ability to compare candidate
   actions at the same state.

7. The coefficients multiplying duration, computation time, and control effort
   were trainable, although the project defines all three coefficients as $1$.
   Lower prediction error was partly obtained by changing these coefficients
   instead of learning the remaining future cost. Offline training changed them
   to approximately $(1.099,0.612,0.630)$, and online training changed them to
   $(0.068,0.208,0.273)$. The critic therefore learned a different cost function
   from the project cost function.

8. The old surface plots assigned the solve time measured for one recorded action
   to every candidate action in the plot. They therefore did not represent how
   solve time changes with $(B,H)$. Deployment instead uses an explicit model
   fitted to Monte Carlo solve-time records to predict solve time for each
   candidate action. The plot calculation and deployment calculation were not the
   same.

9. One gradient update is one parameter adjustment computed from a small sampled
   group of transitions called a minibatch. The online updater made eight updates
   per new transition but discarded all earlier simulation runs from its replay
   data. It also selected the minimum predicted next cost from 1,681 candidate actions, including
   actions with little dataset support, without a conservative penalty that makes
   poorly supported actions more costly. The final mean squared Bellman error,
   which measures disagreement with the one-step cost equation, was $367{,}622$;
   the final minibatch mean squared error was only $14{,}156$. The difference shows
   that the last minibatch did not represent the full one-step consistency error.
   The critic forgot behavior learned from earlier simulation runs and predicted
   some poorly supported actions as too inexpensive.

10. The Monte Carlo generator is confirmed to vary only the initial state
    $(\theta_0,\omega_0)$ for each simulation run and $(\bar B,\bar H)$ at each
    decision. Plant, controller, limits, and cost settings remain fixed. The online
    training process did not use this initial-state variation: all 128 simulation
    runs started from
    $(\theta_0,\omega_0)=(1.57,0)$. It also had no fixed validation set and no rule
    requiring the deterministic policy to pass validation before a checkpoint was
    accepted. The final checkpoint was saved even though the critic had repeatedly
    selected minimum actions and failed.

The offline checkpoint reduced its old validation mean squared error from
$608{,}543$ to $13{,}918$. This shows only that the network predicted the old
recorded targets more accurately. It does not show correct action comparison under
the current action definition or lower cost in complete simulations.

## How To Fix Target Mismatch

The recorded Monte Carlo return is the total cost produced after the current
action when all later actions follow the Monte Carlo behavior policy. It estimates

$$
Q^{\mu}(s,a)
= \mathbb{E}[G_k\mid s_k=s,\,a_k=a,\,a_{j>k}\sim\mu],
$$

where $\mu$ is the uniform Monte Carlo behavior policy. This return is a valid
initial training target, but it is not the cost produced by the deterministic
policy and is not the optimal cost $Q^*$.

Do not select the lowest-cost simulation runs and treat all transitions in those
simulation runs as optimal. Different simulation runs visit different states, so
their costs do not provide a controlled comparison of actions at the same state.

Use three steps:

1. Train an initial critic on recalculated Monte Carlo returns so it learns the
   current state scale, action scale, and behavior-policy cost.
2. Train with a conservative one-step target based on the immediate cost and the
   lowest next-state cost predicted by two target critics. The conservative term
   prevents actions with little dataset support from appearing too inexpensive.
3. Add two focused data types: several candidate actions evaluated from the same
   state, and complete simulation runs generated by the improving deterministic
   policy. Then repeat training with all previous and new training data.

Additional data should focus on comparing actions from the same state and on
recording the policy being learned. Another large set of uniformly random complete
simulation runs is less useful for this purpose.

## The New Model Design

Use two cost critics with separate state and action input networks. Each critic
predicts one scalar total cost. Two critics are used so deployment can choose the
higher, more cautious cost estimate when they disagree. A recurrent network, which
stores information across a sequence, is not required because the state includes
unwrapped angle and remaining simulation time and each transition supplies the
next state for the one-step target.

Collapsed model:

```text
state[7]  -> 64 -> 64 -----------+
                                    concatenate(state, action, state * action)
action[4] -> 32 -> 64 -----------+---------------+
                                                    |
                  +---------------------------------+-------------------+
                  |                                 |                   |
             Q1: 192 -> 128 -> 64 -> 1         immediate: 192 -> 64 -> 1
             Q2: 192 -> 128 -> 64 -> 1         failure:   192 -> 32 -> 1
```

All hidden layers use `SiLU`. The $Q_1$, $Q_2$, and immediate-cost outputs are
positive normalized costs. The failure output is converted to a probability only
inside its binary classification loss. Deployment uses

$$
Q_{\mathrm{deploy}}(s,a)=\max(Q_1(s,a),Q_2(s,a)).
$$

The three project cost coefficients remain fixed at $1$. Training cannot change
the cost function.

## The Training Steps

1. Read `train`, `val`, and `test` directly from their dataset directories.
   Validate complete ordered simulation runs and never reshuffle the test
   simulation runs.
2. Reconstruct the complete state, replace unreliable solve-time measurements with
   a calibrated single-worker estimate, and recalculate immediate costs and Monte
   Carlo returns in memory. Preserve the original CSV files.
3. Train the behavior-policy reference critic on `train` and use `val` to stop
   training when validation error no longer improves.
4. Train the two critics with conservative one-step targets. Give the short- and
   long-horizon data groups equal sampling probability. Select checkpoints using
   validation Bellman error, same-state action comparison, and deterministic
   validation over complete simulation runs. Do not use success in exploratory
   simulation runs for model selection.
5. Generate same-state action comparisons and policy-directed complete simulation
   runs. Keep all earlier training data, retrain, and continue only while
   deterministic validation performance improves.
6. Fix the complete method and selected checkpoint. Use the test set once, then
   compare with unchanged MPC and the historical reference critics on the same
   test states.

# The Details



## Fixed Terms, Contract, And Notation

The definitions in the Quick View apply throughout this section. A cost critic is
a neural network that predicts total future cost. A state is complete for this
task when it contains the information required to predict the next transition and
its future cost. The plant, MPC controller, limits, goal, and cost function remain
unchanged.



### State

The complete decision state used by the critic is

$$
s_k = (\theta_k, \omega_k, t_k, m_k),
$$

where $m_k$ is the live constraint margin. The network receives seven scalar
features:

1. $\sin\theta$;
2. $\cos\theta$;
3. $\omega/\omega_{\mathrm{ref}}$, where
   $\omega_{\mathrm{ref}}=2\sqrt{g/l}$;
4. normalized energy error $(E-E^*)/E^*$;
5. unwrapped angle $\theta_{\mathrm{unwrapped}}/\theta_{\max}$;
6. live constraint margin
   $m_k=\min(\theta_{\max}-|\theta_{\mathrm{unwrapped}}|,\omega_{\max}-|\omega|)$;
7. remaining simulation fraction
   $(N_{\max}-t_{\mathrm{index}})/N_{\max}$.

The last three features distinguish decision situations that the old state mapped
to the same sine, cosine, and angular velocity. The angle component of $m_k$ is the
distance to the configured angle constraint. For current artifacts, unwrapped angle
and $m_k$ are read from `steps.csv` at each `start-t-index`. The first state is
reconstructed from the recorded initial state. Future generators must write these
values directly to `rl_steps.csv`.

### Action

The action is represented by the integer values that MPC executes. Let $H_{\max}$
be the integer horizon for five natural periods. The four action inputs are:

1. realized burst fraction $B/H$;
2. normalized horizon $H/H_{\max}$;
3. normalized burst length $B/H_{\max}$;
4. predicted solve-time feature
   $\log(1+\hat t_{\mathrm{solve}}/\Delta t)$, where
   $\hat t_{\mathrm{solve}}$ is produced by the calibrated solve-time model.

The deployment grid may be constructed from $(\bar B,\bar H)$, but duplicate
realized $(B,H)$ pairs are removed before critic evaluation. Candidate actions use
the data-supported ranges $0.01\leq\bar B\leq1$ and
$0.01\leq\bar H\leq5$.

### Cost And Terminal Meaning

For every transition, independently reconstruct:

$$
c_k = c_{t,k} + c_{u,k} + c_{c,k} + c_{f,k},
$$

with

$$
c_{t,k} = t_{k+1} - t_k, \qquad
c_{u,k} = \sum_i (u_i/u_{\max})^2,
$$

$$
c_{c,k} = \hat t_{\mathrm{solve},k}/\Delta t, \qquad
c_{f,k} = 100\mathbb{1}_{\mathrm{terminal\ failure}}.
$$

`done=True` identifies the final transition but does not identify success. Success
is `goal_reached`; failure is `max_steps_reached`. The outcome is read from the
simulation-run summary and must agree with the final simulator index.

Stored artifacts contain direct costs; no sign conversion is applied. Lower $Q$
is better.

The short-horizon solve-time distribution is bounded in the current data: median
$0.843\ \mathrm{s}$, 99th percentile $4.516\ \mathrm{s}$, and maximum
$5.891\ \mathrm{s}$.

The long-horizon records were generated with changing numbers of parallel workers.
Their measured solve times therefore include both solver work and delays caused by
other processes:


| Long-horizon solve-time statistic    | Value      |
| ------------------------------------ | ---------- |
| median                               | $18.594\ \mathrm{s}$   |
| 90th percentile                      | $169.969\ \mathrm{s}$  |
| 99th percentile                      | $753.234\ \mathrm{s}$  |
| maximum                              | $18{,}147.5\ \mathrm{s}$ |
| simulation runs containing a solve over $60\ \mathrm{s}$ | $551/991$ |

Because compute cost divides solve time by $0.01\ \mathrm{s}$, the largest immediate
cost is $1{,}814{,}834$ and the largest return is $1{,}818{,}818$. These numbers can represent a mix

current files do not contain enough solver-status and process-time evidence to
separate those causes.

Do not silently cap these solve-time values and do not use them directly in the
main $Q$ training target. Build a single-worker calibration set on the deployment
machine. Record wall time, process time, solver status, and iteration count. Repeat
each solve to separate solver delays that reproduce from delays caused by parallel
processes. Fit an explicit model to predict expected single-worker wall time from
the Monte Carlo solve-time records and the calibration records. Recalculate the
training costs with this model while retaining every original solve-time value for
audit. A delay that repeats under single-worker conditions remains part of the
action cost; a parallel-process delay does not.

The saved `current-surface-lasso-20260630T184805` model is a reference model used
only for comparison. It was fitted to 5,081 transition records from earlier mixed
artifact locations. It predicts solve time from $H$, $B$, and $BH$ with root mean
squared error $0.603\ \mathrm{s}$. It has not been validated on the current
five-period data generated with multiple workers.

### Loader Mismatch That Must Be Removed

The current offline loader is not yet compatible with the dataset directories:

- it recursively loads `train`, `val`, and `test` together and then randomly
creates a new train/validation split;
- it has no fixed test path;
- it requires every simulation run to have the same `hbar-max`, so it rejects the two
  action-range configurations even though plant and cost constants match;
- it treats independent transitions, rather than complete simulation runs, as the
  splitting unit.

The new loader reads each directory split explicitly. `hbar-max` describes the
sampled action range; it is not a plant constant and is not a reason to reject a
simulation run.

## Correct Treatment Of The Target



### Behavior-Policy Return Is Only The Initial Target

For the uniform Monte Carlo behavior policy $\mu$, the current backward return is

$$
G_k^\mu = \sum_{j=k}^{T} c_j, \qquad
Q^\mu(s, a) = \mathbb{E}[G_k^\mu \mid s_k = s, a_k = a].
$$

This target is valid after solve-time cost recalculation. Use it to initialize the
state and action input layers and to train a reference critic for the Monte Carlo
behavior policy. Do not keep it as an additional target during final training.
Doing so would continue to train the critic toward the cost of later random actions
instead of the minimum achievable cost.

### Conservative One-Step Target

Maintain primary critics $Q_1$ and $Q_2$. Also maintain target critics $Q_1^-$ and
$Q_2^-$, which are delayed copies used to keep the training target stable. For a
transition that is not final, define the cautious next-state cost

$$
Q_C^-(s', a) = \max(Q_1^-(s', a), Q_2^-(s', a)),
$$

choose

$$
a^* = \arg\min_{a \in \mathcal{A}_{\mathrm{unique}}} Q_C^-(s', a),
$$

and train to

$$
y = c_{\mathrm{calibrated}}
   + (1-d) Q_C^-(s', a^*).
$$

The higher of the two cost estimates is used because the deterministic policy
selects the lowest-cost action. This prevents one unusually low critic estimate
from controlling the selected action. Duplicate realized $(B,H)$ pairs are removed
from the target action grid.

Use this one-step target for the existing data because those data were generated by
a different policy from the policy being trained. A direct three- or five-step
target would include several later random actions and recreate the target mismatch.
Use a multi-step target only for policy-directed simulation runs in which every
included later action follows the same deterministic policy.

### Conservative Dataset-Support Penalty

Conservative Q-Learning (CQL) adds a penalty for candidate actions with little
dataset support. For each critic, use

$$
\mathcal{L}_{\mathrm{CQL}, i}
= \mathbb{E}[Q_i(s, a_{\mathrm{data}})]
 - \mathbb{E}[\operatorname{softmin}_{a \in \mathcal{A}} Q_i(s, a)].
$$

Here, $\operatorname{softmin}$ is a smooth approximation of the minimum. Minimizing
this term increases predicted cost for poorly supported candidate actions that
appear too inexpensive relative to recorded actions. Use normalized costs and
soft-min temperature $1$. Select
$\alpha_{\mathrm{CQL}}\in\{0.01,0.1,1.0\}$ using deterministic validation results.
Do not select it using test data.

## Model Specification



### Torch-Style Structure

An encoder is a small input network that converts raw features to an internal
representation. An output network then converts the combined state-action
representation to one prediction.

```python
state_encoder = Sequential(
    Linear(7, 64), SiLU(),
    Linear(64, 64), SiLU(),
)

action_encoder = Sequential(
    Linear(4, 32), SiLU(),
    Linear(32, 64), SiLU(),
)

pair = concat(state_embedding, action_embedding,
              state_embedding * action_embedding)  # 192

q1 = Sequential(Linear(192, 128), SiLU(),
                Linear(128, 64), SiLU(), Linear(64, 1))
q2 = Sequential(Linear(192, 128), SiLU(),
                Linear(128, 64), SiLU(), Linear(64, 1))
immediate = Sequential(Linear(192, 64), SiLU(), Linear(64, 1))
failure = Sequential(Linear(192, 32), SiLU(), Linear(32, 1))
```

Apply `softplus`, a function that converts a real number to a positive number, to
the two $Q$ outputs and the immediate-cost output after scaling. The failure output
is an unrestricted real number that is converted to a probability inside the
binary classification loss. Calculate every input mean and standard deviation from
`train` only.

This model is intentionally small. Separate state and action encoders preserve a
clear action-comparison path. The element-wise product represents action effects
that depend on pendulum state. `SiLU` produces smoother action-cost surfaces than
the old ReLU network. The difference between $Q_1$ and $Q_2$ identifies uncertain
cost estimates. A separate action-output network is unnecessary because deployment
already evaluates the finite candidate-action grid in one batch.

### Loss

Let $s_Q$ be the median positive recalculated Monte Carlo return in `train`.
Divide immediate costs, returns, and one-step targets by $s_Q$. Do not apply a
logarithm because the one-step cost equation adds immediate and future costs.

The fitted-$Q$ loss is

$$
\mathcal{L} =
\operatorname{Huber}(Q_1, y)
+ \operatorname{Huber}(Q_2, y)
+ \alpha_{\mathrm{CQL}} ( \mathcal{L}_{\mathrm{CQL}, 1}
                        + \mathcal{L}_{\mathrm{CQL}, 2} )
+ 0.25 \operatorname{Huber}(\hat c, c)
+ 0.1 \operatorname{BCE}_{\mathrm{weighted}}(\hat p_f, f).
$$

Huber loss behaves like squared error for small errors and reduces the influence of
very large errors. Weighted binary cross-entropy trains the failure probability
while accounting for the small number of failures. The immediate-cost and failure
outputs help the shared internal representation retain these two physical
quantities. They do not add a new deployment cost; terminal failure cost is already
included in $Q$.

### Sampling And Optimization

Construct each minibatch in three steps:

1. select the short- or long-horizon data group with equal probability;
2. select one simulation run uniformly from that group;
3. select one transition uniformly from that simulation run.

This prevents the 16,397 short-horizon transitions from outweighing the 2,258
long-horizon transitions. It also prevents a long simulation run from being treated
as several independent simulation runs.

An optimizer is the algorithm that adjusts network parameters. A training epoch is
one scheduled pass through the training sampler. Use these fixed initial settings:

- AdamW optimizer, learning rate $3\times10^{-4}$, and weight decay $10^{-5}$;
  weight decay is a small penalty on large parameter values;
- batch size $256$ transitions;
- limit the gradient vector norm to $5$;
- update each target critic by $0.5\%$ of the primary-critic change per update;
- train for at most $300$ epochs and stop after $25$ epochs without validation
  improvement;
- save and export the checkpoint with the best validation result, not the final
  epoch by default.

Initial behavior-policy training uses Huber loss on recalculated $G^\mu$ for at
most $50$ epochs and stops after $10$ epochs without validation improvement. The
following one-step training does not retain the Monte Carlo-return loss.

## New Data Requirements



### Required Solve-Time Calibration

Before final $Q$ training, create a fixed single-worker solve-time experiment on
the deployment workstation. It contains $1{,}728$ solves:

- select $64$ training states, $32$ from each data group, with equal counts in the
  four energy ranges and four remaining-time ranges;
- evaluate the nine actions induced by
  $\bar B\in\{0.10,0.50,1.00\}$ and
  $\bar H\in\{0.10,1.00,5.00\}$, three times per state;
- record wall solve time, process solve time, solver status, iteration count,
  realized $(B,H)$, and state features;
- fit the explicit solve-time model on two repeats and evaluate it on the third;
- retain delays that repeat as high solve-time cost and replace non-repeating
  scheduling delays with predicted single-worker time.

The original Monte Carlo files remain unchanged. Each training checkpoint records
the calibration-file content hash, which identifies the exact calibration file,
and summary statistics for original and recalculated costs.

### Same-State Action Comparisons

Uniformly random complete simulation runs almost never evaluate two actions from
exactly the same state. Create a one-step comparison set:

- choose $128$ source states from `train`, with $64$ from each data group and equal
  counts in the four energy ranges and four remaining-time ranges;
- evaluate the $25$ realized actions induced by
  $\bar B\in\{0.05,0.25,0.50,0.75,1.00\}$ and
  $\bar H\in\{0.05,0.50,1.00,3.00,5.00\}$;
- restore the same complete simulator state before every candidate action;
- execute exactly one burst-coast segment and save immediate cost components,
  next state, terminal status, solver information, and realized $(B,H)$;
- execute with one worker so compute measurements match calibration conditions.

This experiment requires $3{,}200$ candidate segments and directly measures action
effects at the same state. It provides a controlled action comparison that
$3{,}200$ unrelated random simulation runs do not provide.

Store the same-state comparison records under:

```text
artifacts/action-branch-data/train/<source-run>/branches.csv
```

No same-state comparison data enters `val` or `test`. Before model selection,
create a separate fixed validation comparison set. Action regret is the measured
cost difference between the critic-selected candidate action and the lowest-cost
measured candidate action at the same state.

### Policy-Directed Simulation Runs

After training the first conservative critic:

1. keep policy $\pi_r$ unchanged and require it to pass the deterministic
   validation acceptance rule before data collection;
2. generate $256$ new complete training simulation runs from the original
   initial-state sampling range; select the deterministic action with probability
   $0.90$ and a uniformly random action with probability $0.10$;
3. append those complete simulation-run folders under
   `artifacts/montecarlo-data/train` with a policy-source field in their metadata;
4. retrain using all training transitions and the new one-step targets;
5. evaluate the retrained critic without exploration on the unchanged validation
   set;
6. stop adding data after two consecutive rounds without lower validation cost.

Do not retain only the lowest-cost simulation runs. The returns from all simulation
runs estimate $Q^{\pi_r}$ and describe the policy that generated the data. The
one-step minimum over candidate actions defines policy improvement; retrospective
selection of successful simulation runs does not.

Successful exploratory collection is not evidence that $\pi_r$ is usable. The old
training reached the goal in $127$ exploratory simulation runs while its
deterministic checkpoints failed $124$ of $128$ evaluations. Report exploratory
collection success separately and never use it to select a checkpoint.

Collect at least $20$ reproducible long-horizon failure simulation runs so the
failure output has training examples from that data group. These simulation runs
must come from the declared initial-state sampling range or from a separately named
stress-test range. Keep targeted stress tests separate from ordinary Monte Carlo
frequency statistics.

## Ordered Training And Evaluation Procedure



### Data Acceptance Check

1. Read the directory splits separately.
2. Validate every required transition-sequence condition and stop on the first
   invalid simulation run.
3. Reconstruct unwrapped state and all immediate cost components.
4. Apply the fixed solve-time model and recalculate returns.
5. Calculate feature and cost scales from `train` only.
6. Write a checkpoint record containing simulation-run counts, transition counts,
   outcomes, data-group balance, original and recalculated solve-time percentiles,
   and rejected paths.



### Reference Models

1. Record the old $6$-$32$-$16$-$1$ checkpoint metrics. Use it only for comparison;
   do not initialize the new model from it.
2. Record the final online critic as a failed reference: $183$ transitions from
   only the final simulation run, Bellman mean squared error $367{,}621.69$, and deterministic
   termination at the maximum step count.
3. Train a new scalar multilayer perceptron on behavior-policy returns under the
   current data and action definitions.
4. Train the new two-critic architecture only on behavior-policy returns. This
   separates improvement caused by the model structure from improvement caused by
   the one-step target.



### Conservative Policy Improvement

1. Initialize the two critics from the state and action input layers trained on
   behavior-policy returns.
2. Train with the conservative one-step target and delayed target critics.
3. Select the CQL coefficient using `val` only.
4. Require both lower validation Bellman error and lower same-state action regret
   than the behavior-policy reference critic.
5. Reject a checkpoint if its selected actions concentrate at one action-range
   boundary without lower measured cost in the same-state comparison set.
6. Preserve one optimizer, one target-critic pair, and all replay data across
   training rounds. Never replace replay data with only the latest simulation run.



### Training-Data Expansion

1. Generate the same-state action comparison set.
2. Add policy-directed complete simulation runs.
3. Refit the solve-time model if solver or hardware conditions changed.
4. Retrain and compare on the same fixed validation states.
5. Continue only while validation project cost improves without reducing
   success rate.

### Deterministic Validation And Final Test

1. Select and then keep unchanged $32$ validation initial states before model
   selection. Use $16$ from each data configuration and equal counts across the
   initial-angle and initial-angular-velocity ranges.
2. Every five training epochs, run `rl_explore=False` from those states with the
   original 3,000-step limit. Do not double the horizon for checkpoint selection.
3. Report success rate, total project cost and its duration, computation, effort,
   and terminal-failure components; also report completion time, solver time,
   torque integral, same-state action regret, Bellman error, selected $(B,H)$
   counts, and minimum-action selection rate.
4. Reject a checkpoint if its success rate is below the behavior-policy reference
   critic or if it selects more zero/minimum horizons without lower measured cost
   in the same-state comparison set.
5. Among accepted checkpoints, choose the lowest mean project cost and confirm it
   on all $220$ validation initial states.
6. Keep code, input scaling, solve-time model, action grid, and checkpoint
   unchanged. Evaluate the $220$ test initial states once and compare with MPC, the
   offline critic, the failed final online critic, and the behavior-policy reference
   critic.

Exploratory simulation runs produce training data. Only deterministic evaluations
over multiple fixed initial states measure the policy intended for deployment.
