# JAX Rotary Environment: Validation Matrix

These are proposed tests and pass criteria. They must be run when code exists; documentation alone does not establish that the 50 Hz model is accurate or fast. The reference is the current NumPy model with nominal configuration, including its 2 ms RK4 step. Store test seeds and generated-state arrays when a benchmark is executed so comparisons can be recreated.

| ID | Milestone | Procedure | Pass flag | Failure implication |
|---|---|---|---|---|
| V00 | M0 | Run the existing rotary test subset before and after implementation | All previously passing tests remain passing; no old MPC/NumPy behavior changed | New implementation disturbed the reference |
| V01 | M1 | Compare CPU float64 JAX `state_derivative` with NumPy on 4,096 states, each paired with $-u_{\max},0,+u_{\max}$ | Maximum absolute component difference $\leq10^{-9}$ in state-derivative units; all finite | Algebra, state order, or constants differ |
| V02 | M1 | Compare one 20 ms CPU float64 JAX RK4 result against one 20 ms NumPy RK4 result on the same cases | Maximum absolute angle difference $\leq10^{-9}$ rad; velocity difference $\leq10^{-8}$ rad/s | JAX discretization is not the intended RK4 map |
| V03 | M1 | Compare one 100 ms held-action transition (five 20 ms steps) to 50 reference 2 ms steps over those states and actions | Maximum angle error $\leq0.02$ rad and maximum rate error $\leq0.5$ rad/s; all finite | 50 Hz may be too coarse for the declared operating range; revise step/model before RL |
| V04 | M1/M4 | Repeat V03 with deployment float32 versus the 2 ms float64 reference | Same physical error limits as V03; record worst and 99th-percentile errors by stratum | GPU precision may be inadequate, even if float64 algebra matches |
| V05 | M2 | Draw 10,000 seeded resets per stratum; test bounds, both swing signs, nonzero sample variance, exact seed replay | All samples in their declared support; both signs seen; replay bitwise-identical on one backend | Sampling is degenerate, out of range, or non-reproducible |
| V06 | M2 | Start just inside each arm boundary with outward velocity; integrate a held action | Violation set at first sampled state satisfying $|\theta|\geq\pi/2$; no additional physics steps within that action | Constraint is late or incorrectly soft |
| V07 | M2 | Enter the four-coordinate goal, stay for four samples, then five; separately leave after three | Success false until fifth consecutive sample; leaving resets count; initial goal state starts count zero | Goal semantics differ from agreed 100 ms hold |
| V08 | M2 | Hold a nonterminal state for 1,000 physics steps, then call `step` again | Timeout true at exactly step 1000 (20 s); state and count unchanged thereafter | Episode horizon or done masking is wrong |
| V09 | M2 | Compare eager and `jit(vmap(step))` batched transitions; scan 200 decisions; differentiate raw RK4 map | Equal outputs within dtype roundoff; finite $4\times4$ state and length-4 input Jacobians | Pure-function or transformation contract is broken |
| V10 | M4 | Discover devices on the server and run compiled 200-decision batches of 1,024, 8,192, and 65,536 on one L40S | At least 8,192 full episodes execute without OOM; GPU completed-rollout throughput exceeds CPU at 8,192, with V04 still passing | Optimize layout/precision or revise capacity claim before training |

For V01–V04, generate the 4,096 states as fixed seeded approximately equal allocations from the three proposed reset strata plus arm-boundary and high-velocity edge cases; publish the exact generation seed and arrays. $u_{\max}=0.0204$ N·m is the existing nominal torque limit. Compare each state component separately; a single Euclidean norm would mix angles and rates. The V03/V04 bounds are **proposed gates**, not results. If they fail, inspect per-stratum errors and the states causing them before altering tolerances; do not silently relax a gate. Long 20-second trajectories near unstable upright should be assessed by outcomes and physical diagnostics, not strict sample-by-sample agreement after small numerical differences have amplified.

V06 only establishes detection at sampled 20 ms physics states. Also search reference 2 ms trajectories for excursions between adjacent 20 ms samples in the declared reset/torque domain. If such excursions are observed at a material rate, the 50 Hz event rule is inadequate even if V06 passes; either refine event detection or revisit the physics step. Record any observed between-sample misses explicitly.

Benchmark timing excludes first compilation, warms the exact shape/dtype combination, waits on output completion, and separates time spent moving arrays across the host/device boundary. Use one fixed dtype and compilation setting per comparison. Report completed physics transitions per second, complete 200-decision rollouts per second, compile time, peak accelerator memory, and the tested batch size. The supplied server inventory (8 L40S, driver 580.126.09) must be confirmed live with `nvidia-smi` and `jax.devices()` before reporting GPU results; no remote run has been performed for this plan.

When actual validation artifacts are generated, keep an updated short judgment in `../interpretation_summary.md` or a similarly accessible human-readable result, any plots under `human-readables/`, and raw test/benchmark tables plus seeds under `machine-scannables/`. The latter may use CSV/JSON because they are measurements, while this planning contract remains Markdown. Never mix an unverified proposal with a measured success flag.
